## 当前定位

截至 2026-11-26，第 7～11 步的本机业务验证完成，第 12 步源码、跨端合成流程及小程序开发包上传完成；**当前正从第 12 步转入第 14 步的实际服务器部署准备**。本轮完成 020 离线配置生成/校验：专项 6/6、完整 Node 226/226，未连接服务器或生成正式部署凭据。原生功能沿用此前 15/15 及开发者工具扫描证据，本轮未重复运行未改动的小程序测试。

已上传 [GitHub 仓库](https://github.com/wanjinrong9-blip/bsr_ski_rental_sad)：网页与小程序源码、4.13 设计需求 PDF、LaTeX 图源和需求/规约/追溯资料；小程序 `0.1.1` 为开发版本，未审核、未发布。真实支付、退款与电子签署仍为模拟，正式营业接口属于第 13 步的另行确认范围。

下一步依次是：目标 Ubuntu 的运行/私有存储/合成库/异机备份和容量验证 → 网站备案与 HTTPS 入口 → 微信合法请求域名和私有服务端配置 → 审核专用账号、隐私指引及真机跨端验收 → 提交微信审核 → 审核通过后发布并启用官方扫码入口。ICP备案仍在审核；微信后台地址被电脑控制工具禁止访问，相关后台设置须用户手动操作。

用户已购买阿里云轻量应用服务器与 `bsrski.cn`；实例为**广州 Ubuntu 24.04、2 vCPU / 2 GiB、40 GiB 单系统盘**。此前只核验控制台并禁用 Web 端口；代码已交付 GitHub，但尚未上传到阿里云或部署。网站 ICP 订单 11 月 20 日曾因“网站主办者冲突”退回；据用户当前说明域名仍在审核，现状应以备案控制台为准。系统盘版模板、目标机容量、异机备份和恢复、SSH 管理来源及域名证书门槛见 [云端预览准备](云端预览准备.md)。SQLite 单实例持久存储、受控访问和恢复验证仍是实际部署门槛。

2026-11-12 的备份审阅记录：011 的新备份流程已避免产生临时 WAL/SHM 残留；既有备份目录当时仍有 6 个旧残留文件，自动审批策略拦截了清理操作。备份目录含敏感演示数据，不纳入代码发布。
