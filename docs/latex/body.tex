\subsection{1.1 项目背景}

BSR 自 1961 年起在挪威 Skardalen 滑雪度假村经营高端装备日租业务。度假村计划在山另一侧开设第二家租赁点，并要求 BSR 在一个月内提交扩张方案。现有 Excel 工作簿每次只允许一人可靠操作，客户、装备、合同和维修信息还混杂在纸面流程中，无法支撑两店并行、线上预约和跨店库存管理。

新系统采用 B S 架构，为顾客提供响应式网页和移动端 H5，为店员、维修分包商、门店经理和系统管理员提供分角色工作台。第一阶段的业务主线是顾客线上选择装备和取货日期，系统按日期筛选库存并展示租金、押金和归还时间；支付成功后生成一次性取货码；顾客到店与店员共同验货并取走装备；归还时逐件验收；无异常订单自动发起押金原路退回。

\subsection{1.3 设计结论}

\begin{itemize}
\item
  预约按装备规格记录所需数量，门店备货和交付时再逐件绑定库存编号。案例中每件实物均有唯一库存编号；即使合同将同款雪杖合并显示为数量，借还、验收与维修仍逐件追踪。
\item
  可用库存必须按门店和租期区间计算，不能只看当前在库数量。库存占用、已确认预约、已借出、维修、隔离和调拨中的数量均不可再次出售。
\item
  订单必须保存价格快照。后续价格或押金政策调整不能改变已确认订单、已签合同或历史账单。
\item
  顾客端展示本门店、本取还日期、所选规格与租期对应的已批准价格；多日套餐须按政策表计算，不以一日价直接乘天数。租金、押金和可能产生的逾期费用要分别说明；仅在业务方批准提供可选保障服务时另列该项费用。
\item
  取货码仅用于定位和核验订单，不替代身份确认、电子签署和现场验货。取货成功后立即失效，禁止重复使用。
\item
  押金自动退款不是简单的定时任务。只有全部租赁项目已归还、逐件验收完成、逾期和损坏费用已确定、无待处理争议且支付记录可用时，系统才可自动退款。
\item
  付款、退款、通知和库存变更必须可重试且幂等。重复回调不得产生重复合同、重复扣款或重复退款。
\end{itemize}
