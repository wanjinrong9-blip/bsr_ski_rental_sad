## 必须保留的差距与决策

1. **业务方签字**：取还时刻、10%/小时、首租宽限、24 小时封顶、8%押金、损坏估值、异议期限、取消与退款承诺都属于演示政策。正式规则需 BSR 确认、版本化发布，并做挪威市场及适用法规复核。
2. **外部交易**：当前支付、退款、补差均只是数据库演示流水。真实支付服务商、回调验签、幂等、对账、退款失败补偿、账务及税务未接入；不能据此声称已收款/已退到银行卡。
3. **合同签署顺序**：本地线上和现场都执行“当前版先确认、再演示付款”。线上本人电子确认不等于合格电子签章；正式预授权、签署和扣款节点仍需 BSR 决定，再接入合格签署与第三方支付服务。
4. **奖金与权限**：系统提供按年度的归属业绩数据，但未假定奖金比例或自动发薪。案例中“员工均可拟制合同”与本系统按岗位限制现场开单存在差距；应由 BSR 确认是否采用培训资格/授权标识，并保留审计。
5. **安全与规模**：演示账号和本地数据库只供课程使用。013 回环及静态边界已验；014 新候选库、受控账号和本机 HTTPS 会话已有隔离证据，仍非公网服务。正式环境仍需身份核验渠道、强凭据与秘密轮换、多因素或等效保护、轮岗临时授权、完整对象权限审计、公开 TLS/网络入口、隐私告知与保存期限、备份加密、异地保管、周期调度、RPO/RTO、数据库选型、并发与多门店性能测试、监控告警。
6. **文档一致性**：现行已编译设计需求文档为 v4.11，78 页 A4；保留六章与已复核课堂图例，附录 G/H/I 分别记录 014、015、016。封面、概览和附录 I 两页已渲染抽查，未见文字或表格重叠。其业务与技术追溯不能代替 BSR 对现场流程和政策的确认。005 的复核另见 `specs/005-fulfillment/review.md`。
