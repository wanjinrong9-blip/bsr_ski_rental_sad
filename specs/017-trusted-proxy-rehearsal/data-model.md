# 017 配置与请求数据模型

017 不新增业务表、顾客字段、合同快照或 ERD 实体。此处描述入口配置和可信请求上下文如何映射到既有存储。

## 入口配置（仅进程内）

| 字段 | 来源与规则 | 存储 |
| --- | --- | --- |
| `runMode` | 现有 `demo` 或 `candidate`；代理传输仅允许后者 | 进程内；候选来源标记仍在 `runtime_installation` |
| `candidateTransport` | `direct-tls`（默认）或 `trusted-local-proxy` | 进程内，不写数据库 |
| `host`、`port` | 两种候选传输和 demo 都只准回环地址及合法端口 | 进程内 |
| `publicOrigin` | 唯一外部 HTTPS 来源；直连须与回环 Host/端口一致，代理可为未来独立域名 | 进程内 |
| `proxySecret` | 仅代理传输，来自私有环境；只保留进程内值，不在日志/响应显示 | 进程内 |
| `tls` | 直连候选使用本机证书/密钥；代理候选由前置 HTTPS 代理处理 | 私有文件路径；不写业务库 |
| `dbPath`、`backupDir` | 独立候选数据库与已存在私有备份目录，不得位于公开静态目录 | 私有文件系统 |

## 可信请求上下文（仅请求内）

| 字段 | 接受条件 | 后续用途 |
| --- | --- | --- |
| 实际 peer | 内部 Node 仅绑定回环；代理必须同机访问 | 物理入口初筛 |
| 唯一 Host | 与配置中的外部 HTTPS origin 的 host 严格一致 | 防主机混淆 |
| 代理凭据 | 唯一非空头，固定时序比较 | 证明请求经受控代理；先于业务路由 |
| 转发协议 | 唯一 `https` 值 | 防意外非 TLS 外部入口 |
| 客户地址 | 代理覆盖访客值后的单个有效 IP；不得来自原始转发链 | 候选登录来源限速 |
| Origin | 写入请求须等于配置中的外部 HTTPS origin | 既有 CSRF 来源门槛 |

缺失或重复的安全字段使请求被拒；失败请求不构造可信客户地址。任何静态、健康、SSE 与 API 路由都不例外。

## 既有表与兼容

- `runtime_installation` 仍标记独立候选来源；017 不更改其结构或版本。
- `sessions` 仍保存候选 Cookie 的令牌哈希、撤销及过期信息；Cookie 名、Secure/HttpOnly/SameSite 属性不变。
- `auth_attempt_buckets` 的 `SOURCE` 维度继续使用实例标识与来源地址的哈希；代理模式的来源改为已验证客户 IP，直连仍为 socket 地址。没有新增明文 IP 表。
- `audit_log` 仍记录原有候选身份/配置安全事件，不能记录代理密钥；若拒绝请求尚未进入数据库，至少由代理/进程的最小日志留痕，不以此为由绕过入口。
- `stores`、`variants`、`reservations` 等候选业务表保持空目录/既有交易门槛；不从 demo 数据库复制。

## 状态和恢复

配置无效 → **拒绝启动（未打开候选库）**；有效代理配置 → **仅回环监听** → 逐请求校验成功后进入既有候选身份/路由。代理密钥轮换须协调代理和应用同时更新，失败时保持关闭；不能在两个密钥之间自动降级。重启或恢复后候选来源标记、角色与会话撤销规则仍以既有库为准，恢复命令继续使快照里的旧会话失效。
