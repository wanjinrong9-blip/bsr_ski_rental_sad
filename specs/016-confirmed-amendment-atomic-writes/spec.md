# Feature Specification: 顾客确认换装与主数据原子写入

**Feature Directory**: `specs/016-confirmed-amendment-atomic-writes`  
**Created**: 2026-11-17  
**Status**: 本机自动化与隔离浏览器验收完成；SC-001 的真实用户 2 分钟辨识仍待观察，不代表 BSR 验收或正式上线  
**Input**: 005 历史复核的剩余本地缺口：店员口头/纸质见证不能冒充顾客本人确认换装；顾客、员工、价目、库存等主数据写入和审计须在失败时保持一致。

## User Scenarios & Testing

### User Story 1 - 顾客本人确认本次换装（Priority: P1）

已在租赁中的顾客由门店提出换装方案。顾客在自己的订单中看到退回与新增单件、租金和押金差额、NOK 净额、现有合同版本、有效期限与演示交易提示，主动确认。门店在确认后再次核验实物与报价，才办理换装。顾客拒绝、未确认、草案过期或内容改变时，门店不能把勾选“已签纸质变更”当成顾客本人确认。

**Why this priority**: 换装会改变顾客正在使用的装备及应收、应退金额；本人知情是合同可信的前提。

**Independent Test**: 用一张已交付订单提出换装，分别以店员与顾客账号尝试查看、确认和执行；逐步比对合同版本、金额、实物绑定及事件。

**Acceptance Scenarios**:

1. **Given** 合同有效、门店有可用装备，**When** 本店专员提出具体换装方案，**Then** 本单顾客在自己的订单中看到冻结的单件明细、NOK 租金/押金/净额、版本和到期时间；此时合同、已租实物及金额仍不改变。
2. **Given** 顾客已阅读当前未过期方案，**When** 顾客在自己的会话中核对后明确确认，**Then** 留下顾客账号、方案内容摘要、合同版本及时间的确认记录；店员不能代替顾客提交该确认。
3. **Given** 本人确认仍有效，**When** 本店专员完成现场完好检查、新装备安全检查和现有纸质见证后提交，**Then** 新合同、单件借还、分列的租金/押金差额与已消费方案一致，旧合同保留；顾客能看到结果及演示资金标识。
4. **Given** 顾客未确认、明确拒绝、方案过期、合同版本改变、库存变化或报价不一致，**When** 门店尝试提交，**Then** 系统拒绝并要求重新提出/确认；不改变单件、合同、应收应退、方案确认事实。
5. **Given** 网络响应丢失，**When** 顾客重复确认或店员使用相同提交标识重试，**Then** 返回同一确认或同一变更结果；相同标识换内容被拒，不重复换装、记账或通知。

### User Story 2 - 主数据与审计一同成功或失败（Priority: P2）

门店和管理员保存顾客档案、员工资料、承包费率、门店、采购单件、清洁放行及价目时，系统应让资料变化和对应的处理记录保持一一对应。发生写入错误或同事同时操作时，不应出现“数据变了但没有审计记录”或“审计声称已改变、数据却没改”的状态。

**Why this priority**: 这些主数据会影响合同金额、库存可用性、员工责任和争议追溯。

**Independent Test**: 在隔离数据库逐一调用各岗位的有效与无效写入，并注入审计写入故障；比较业务表、审计表及通知的前后快照。

**Acceptance Scenarios**:

1. **Given** 有权限的用户提供有效资料，**When** 保存成功，**Then** 业务资料与一条可归属处理人的审计记录同时可读；适用时通知与版本也一致。
2. **Given** 审计记录无法保存或后续步骤失败，**When** 同一次写入返回错误，**Then** 业务资料、审计和通知都回到操作前状态。
3. **Given** 重复邮箱、门店名称、库存编号、同日费率或同版价目，或两个操作并发竞争唯一值，**When** 保存，**Then** 至多一个有效结果，失败者不留下半成品或伪成功审计。
4. **Given** 顾客、异店员工或不符岗位权限的账号，**When** 试图修改受限主数据，**Then** 在对象与角色校验处拒绝，其他门店和顾客记录不变。

### Edge Cases

- 一个方案在顾客确认前被门店更正时，旧方案应标为已取代；已确认且未过期的方案不得被员工悄悄替换。
- 顾客在 A 标签查看方案、B 标签确认后，A 标签的旧画面不能再次产生不同结果。
- 顾客只可看本人换装方案；经营汇总、技师和异店岗位不可通过猜测编号读取姓名、单件或差价。
- 方案确认是本地账号内的主动记录，并非银行支付或具法律资格的电子签章。纸质签署见证与本人线上确认须分别显示。
- 历史合同变更没有本人确认记录，仍按原事实展示为“历史人工见证”，不得补造确认。
- 主数据并发控制按对象既有恒定键、唯一约束及适用版本决定；不为所有表机械新增无业务意义的版本号。

## Requirements

### Functional Requirements

- **FR-001**: 本店有权限的员工只能为未逾期、已交付且仍有效的本店租赁提出换装草案；顾客本人可在订单中查看冻结的退/增单件、租金差额、押金差额、NOK 净额、原合同版本、报价截止时间和演示标识。提出与查看不改变原订单、金额及实物。
- **FR-002**: 每个草案须有稳定编号、提交标识、内容摘要、创建人和创建时间；相同提交重复返回同一草案，不同内容复用标识须拒绝。未确认草案可被更正版取代，已确认且有效的草案不得被员工静默覆盖。
- **FR-003**: 只有该订单顾客本人能对未过期、未被取代且与当前合同版本一致的草案明确确认或拒绝；记录账号、动作、准确摘要和时间。员工与其他顾客不能代确认。相同动作重试不得产生多条确认。
- **FR-004**: 门店提交换装前必须同时满足本人确认、草案有效、内容/版本/价格一致、当前库存可用、退回项完好、新增项安全检查及原有纸质见证要求。任一条件失败不改变单件、合同、金额、确认记录或通知；过期或变化须重新报价和确认。
- **FR-005**: 成功提交只能消费一次已确认草案，在同一业务步骤中保存单件借还、原订单金额、合同新版本、独立租金/押金差额、办理人及审计；历史合同与旧变更事实不回写。
- **FR-006**: 顾客和本店经办可看到草案状态与时间线；顾客只能看本人内容，其他门店、技师及汇总岗位不得读取个体草案。界面须清晰区分“顾客本人确认”“门店纸质签署见证”和“演示收退”。
- **FR-007**: 顾客资料、现场建档、员工资料、承包费率、门店、采购单件、清洁放行及价目政策写入须使业务变更与审计记录共同成功或共同失败；保存成功记录处理人、对象与时间。
- **FR-008**: 各主数据入口继续执行现有岗位/门店权限及唯一键约束；失败的校验、审计故障、重复提交与并发竞争不得留下业务或通知半成品。只有确有并发覆盖风险的对象才增加版本校验。
- **FR-009**: 历史变更若无本人确认记录，读取时标为历史人工见证；不得回填顾客确认或将本地确认称为合格电子签署、真实资金到账。

### Key Entities

- **换装草案**：归属订单与原合同版本，冻结单件明细、NOK 差额、内容摘要和到期时间；有待确认、本人确认、拒绝、已取代、已过期、已执行状态。
- **顾客确认事实**：一名订单顾客对一个准确草案的主动动作、时间、账号与摘要；与员工纸质见证分开。
- **合同变更**：最终执行记录，关联一个本人确认草案与新合同版本；历史记录可无草案关联。
- **主数据与审计事件**：顾客/员工/门店/费率/价目/单件状态等对象及其经办痕迹，一次业务提交内保持一致。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 顾客在本人订单打开有效草案，可在 2 分钟内指出退/增装备、租金和押金差额、NOK 净额、截止时间及当前责任人；隔离浏览器桌面与 390px 页面均可读、无整页横向溢出。
- **SC-002**: 未确认、被拒、过期、跨账号、跨店、旧合同版本和变更内容不一致等至少 10 组样本均不能提交换装，单件/金额/合同/事件/通知差异为 0。
- **SC-003**: 已确认方案成功换装 1 次，重复顾客确认及重复员工提交均不产生第二次实物、金额、合同或通知；历史变更的原记录与快照不变。
- **SC-004**: 所列主数据入口的有效写入和审计一一对应；至少 7 类业务写入的故障注入使业务、审计、通知差异均为 0，唯一值并发最多一个成功。
- **SC-005**: 完整自动测试和隔离浏览器流程通过；候选环境仍保持未批准目录和交易关闭，演示确认/签署/资金文案不会误导为正式服务。

## Assumptions

- 016 先在课程演示环境实施。014 候选运行仍关闭未获 BSR 批准的目录、价格和换装交易。
- 顾客本人确认以现有登录会话为本地证据，不能证明法定身份或替代合格电子签署。
- 继续沿用现有 5 分钟报价有效期与 NOK 演示价目；如需更长有效期或正式换装计费规则，须由 BSR 确认后另定政策版本。
- 主数据写入范围限本包列举的入口；已有员工资料事务作为回归基线，不扩大到全部业务写入。

## Out of Scope

- 真实支付、退款、银行对账、具有法律效力的电子签署、正式价目、跨店轮岗及奖金。
- 对 005 历史订单重新索要本人确认或修改已签合同快照。
- Git 初始化、上传 GitHub、购买/开放云服务及对外部署。
