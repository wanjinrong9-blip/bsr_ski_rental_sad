# Feature Specification: 网页与微信小程序共享租赁业务

**Feature Directory**: `specs/019-wechat-mini-program`  
**Created**: 2026-11-18  
**Status (2026-11-25)**: 本机源码与正式 AppID 模拟器编译已完成；真实微信身份绑定、正式扫码及发布未完成
**Input**: 用户要求保留现有网页，再建设可通过网页扫码进入、与网页库存和订单互通的微信小程序。用户仍要求在满意前不上传 GitHub、不开放云端访问。

## Scope and meaning

微信小程序是运行在微信中的**独立客户端**，网页和小程序访问同一个受控业务服务及同一套订单、库存事实。小程序代码需通过微信开发者工具、微信公众平台上传和审核；它不作为网页的一段静态文件“部署在网页上”。网页上的扫码入口展示由微信平台签发的小程序码；扫码在微信内打开小程序。用户已提供正式 AppID `wx51ce51fc873371a6`、小程序名称 `WJR同学的BSR系统分析设计作业` 和小程序备案号 `湘ICP备2026056763号-1X`；开发者工具项目已核对 AppID，但 `bsrski.cn` 域名 ICP 仍在审核。合法 HTTPS 请求域名、私有平台凭据、真实微信账号/真机验证、平台审核和对外发布仍属后续条件。

首版小程序面向**顾客**：浏览目录、按日期区间看库存、购物车、费用和协议、预约、本人订单、取货码与履约/受损进度。门店租赁专员、经理、技师、经营负责人和权限管理员继续在网页工作台操作；其更新需立即反映到小程序顾客视图。员工小程序工作台为后续独立规格，不以开放员工 API 代替。

## User Scenarios & Testing

### User Story 1 - 顾客在网页扫码进入小程序（Priority: P1）

顾客在网页的明确入口看到 BSR 微信小程序码与简短说明，使用微信扫一扫打开顾客首页。网页和小程序应说明这是两个入口、共享同一业务资料；扫码本身不自动授予顾客账户权限。未取得真实可用小程序码时网页展示“微信小程序筹备中”，不显示假码或失效码。

**Why this priority**: 用户需要同时展示网页与小程序，并让老师可以理解两者如何互联。

**Independent Test**: 在本地模拟配置下检查入口状态和无假码；正式 AppID 已配置，待合法域名、真实小程序码与微信测试资格齐备后用手机扫码，核对进入的页面、场景参数、未登录提示及错误码处理。

**Acceptance Scenarios**:

1. **Given** 微信平台签发的有效小程序码已由管理员配置且站点已获发布批准，**When** 顾客使用微信扫一扫网页上的码，**Then** 打开指定小程序的顾客首页或受控商品页；二维码参数不含会话、联系方式、订单号明文或权限。
2. **Given** 小程序尚未获平台发布或码未取得，**When** 顾客查看网页入口，**Then** 只看到可理解的筹备状态与网页继续使用入口，不能扫描到一个假的网页二维码。
3. **Given** 扫码参数过期、被修改或指向不允许的页面，**When** 小程序启动，**Then** 安全回退到顾客首页，不自动登录、不泄露订单。

### User Story 2 - 顾客在两端看到相同库存、价格和订单（Priority: P1）

顾客在小程序先选门店、起租日期（当地 09:00 后）和归还日期（当地 16:00 前），再按分类、尺码和款式筛选剩余设备。顾客将滑雪装备、雪镜、护膝等加入购物车，核对 NOK 租金、逐件参考价值 8% 押金、损坏与超时规则并勾选同意后预约。已登录顾客在网页和小程序看到同一份购物车；网页员工备货、交付、归还和检修的每一步，顾客在小程序订单里看到同一状态、处理岗位/责任人和时间。顾客在两个入口之间切换时，订单不可分叉或重复扣费。

**Why this priority**: “互联”要求共用同一业务事实，而不是两个仅外观相似的独立演示。

**Independent Test**: 对一个合成顾客账号，用网页及小程序测试客户端分别查询同一日期窗口、提交一笔订单、让员工网页端推进至归还和鉴定，再核对两端订单快照、库存和提醒。

**Acceptance Scenarios**:

1. **Given** 同一门店和日期区间，**When** 网页和小程序同时查询，**Then** 规格、剩余单件数、NOK 价格及政策版本一致；页面缓存不能覆盖服务端重新核算的结果。
2. **Given** 同一已登录顾客在网页修改购物车，**When** 小程序再次读取或修改，**Then** 看到最新购物车版本；基于旧版本提交会收到冲突提示，不覆盖另一个入口的修改。
3. **Given** 顾客在小程序购物车中放入多件设备，**When** 提交预约，**Then** 服务端重新检查库存、政策同意和价格；只创建一次订单，网页端立即能看到相同的订单和库存占用。
4. **Given** 网页员工已备货、核码交付或登记归还，**When** 顾客刷新/重新打开小程序订单，**Then** 显示最新阶段、责任人、时间、预计归还时间与取货码，且只显示本人订单。
5. **Given** 归还后技师在 24 小时内提交受损照片与等级，**When** 经理复核并模拟结算，**Then** 小程序显示受损说明、押金抵扣、应退/补差和处理进度；“退款”和“联系”仍明确标为模拟。
6. **Given** 两端同时预订最后一件，**When** 两次提交并发，**Then** 至多一单成功；失败端收到可理解的库存变动提示，购物车数据仍可修改后重试。

### User Story 3 - 顾客安全关联网页与微信身份（Priority: P1）

顾客在小程序使用微信提供的临时登录凭证启动登录，再通过现有网页顾客账号的明确验证完成绑定。微信身份标识只用于找到已绑定的顾客，不等于任何员工权限。顾客可在受控界面解除绑定、退出并撤销小程序会话。新用户自助注册是否开启沿用运行模式和现有账号政策，不因安装小程序而自动放开。

**Why this priority**: 微信 OpenID 与本站顾客账号不是天然同一身份；错误自动合并会泄露订单。

**Independent Test**: 模拟微信凭证交换的成功、一次性使用、错误 AppID、重复绑定、账号停用和会话撤销；再用真实微信测试账号完成端到端绑定，检查本人/他人订单隔离。

**Acceptance Scenarios**:

1. **Given** 微信身份尚未关联，**When** 顾客在小程序登录，**Then** 只能访问公开目录；须证明控制某一现有顾客账号后才能读取该账号订单。
2. **Given** 顾客完成账号验证和明确绑定，**When** 小程序再次登录，**Then** 系统将该微信身份解析为同一个顾客 ID；两端订单相同，网页会话与小程序会话可以分别退出。
3. **Given** 同一微信身份已绑定顾客 A，**When** 尝试绑定顾客 B 或员工账号，**Then** 拒绝且双方订单和权限不变；重复验证码、临时登录凭证或绑定挑战不能重放。
4. **Given** 顾客账号被停用或微信绑定被解除，**When** 使用旧小程序令牌重试，**Then** 私有 API 拒绝，已下载的私有缓存按策略清理。

### Edge Cases

- 手机微信扫一扫、微信内网页和桌面浏览器对小程序码的打开方式不同；只承诺真实微信扫码，不把普通浏览器 QR 识别当作正式小程序测试。
- 小程序未注册/未审核/未发布、AppID 变更、平台接口限额或生成码失败；网页入口保持筹备/故障状态，不复用别的小程序码。
- 微信临时 `code` 被复用、伪造响应、错误 AppID、网络超时；任何失败不能创建或绑定账号。
- 不同微信身份试图绑定同一顾客；只有经过现有账号验证及显式换绑流程才能改变关系，操作审计留痕。
- 微信登录正常但现有账号被禁用、必须改密、权限变化或会话已撤销；小程序不能靠本地缓存延续权限。
- 浏览器网站的 Cookie/Origin 安全检查与小程序的令牌传输不同；小程序不得伪造网页 Origin 或绕过可信代理。
- 多端并发预约、订单取消、价格/政策变更、最后一件、跨夏令时日期、网络断线后重试；服务端现有规则最终裁决。
- 照片、姓名、手机号、微信身份标识和会话不能出现在公开网页二维码、日志、仓库、静态目录或匿名接口。
- 由于 018 合成预览尚未实现，不能直接公开当前包含教学账号的 `DEMO` 数据库；019 完整验收依赖 018 安全合成环境。

## Requirements

### Functional Requirements

- **FR-001**: 保留现有完整网页；新增独立微信小程序顾客客户端。两端共用一套服务端订单、单件库存、政策快照和角色权限，不建立第二套可独立修改的库存/订单库。
- **FR-002**: 网页应提供清晰的小程序扫码入口。只有真实、与配置 AppID 匹配且可用的微信小程序码通过服务端受控配置被展示；未就绪时显示筹备状态，不展示假码或开发者工具临时码。
- **FR-003**: 小程序入口如携带参数，只能携带不含个人资料的场景标识或公开商品引用；服务端校验状态、允许页面和上下文，若设置有效期还须校验未过期。扫码不得作为登录证明或传递网页会话。
- **FR-004**: 小程序首页、目录、筛选、时间段剩余库存、购物车、政策阅读/勾选、报价、预约、本人订单、取货码、备货/交还/损坏进度须可用；已登录顾客的购物车须与网页共享且有版本冲突处理，行为与既有服务端业务规约一致。
- **FR-005**: 小程序下单前必须明示 NOK 租金、每件参考价值 8% 押金、09:00/16:00 时段、超时费用与新顾客两小时宽限、损坏分级及退押/补差规则；保存确认时的政策版本和金额快照。
- **FR-006**: 服务端须按同一顾客 ID、门店、物理单件和时间窗口处理两端请求；每次预约再校验库存及同意记录，并对重复提交和并发最后一件提供幂等/冲突控制。
- **FR-007**: 小程序使用微信临时登录凭证经服务端与微信接口交换身份，再签发本站受控会话；AppSecret、`session_key` 和小程序码平台凭据只保存在服务端私有环境，不下发客户端或写日志。
- **FR-008**: 微信身份与本站顾客账号必须通过显式验证后绑定；唯一绑定、解绑、停用、换绑和撤销可审计。不得从微信身份推断员工、经理、技师、经营负责人或管理员权限。
- **FR-009**: 网页继续使用现有受保护 Cookie/Origin 流程；小程序使用独立会话传输并经同等账号、对象、来源和失效校验。两个客户端退出可分别撤销令牌，账号停用须令两端后续请求失效。
- **FR-010**: 小程序顾客仅能读取/修改本人允许的资料和订单；员工在网页上的库存、备货、交付、检修及结算更新需被小程序读取到，不向小程序开放员工写入入口。
- **FR-011**: 在 SHOWCASE 测试环境中，小程序和网页对模拟支付、退款、签署、补差联系及合成数据必须持续标识。不得将模拟状态称为真实到账或有效签署。
- **FR-012**: 小程序只能通过已配置的 HTTPS 合法业务域名访问服务；网络错误、离线重试、版本差异和平台限流须有用户可理解的失败处理，禁止使用本机 HTTP 或 IP 地址作为正式配置。
- **FR-013**: 小程序网页二维码的生成/更新、AppID、微信平台密钥、业务域名、备案/审核状态和发布时间必须由受控部署流程管理；未具备真实平台条件时保持入口关闭。公开站点和 GitHub 上传仍需用户授权。
- **FR-014**: 需求、设计需求文档的执行者/系统用例/序列图、数据模型与接口契约须更新为两客户端架构；图示沿用课程示例风格并避免重叠。云端部署准备信息不写入核心业务设计 PDF。
- **FR-015**: 新增自动化测试覆盖跨端共享状态、扫码场景、防重放、绑定唯一性、对象权限、库存并发、模式隔离、离线重试和无平台凭据状态；使用正式 AppID 在微信开发者工具验证后，还须在合法网络环境中完成真机验证。

### Key Entities

- **小程序配置**：AppID、环境、可用状态、合法业务域名、小程序首页及码版本；AppSecret 和平台访问凭据独立存于私有配置，绝不进公开数据。
- **网页扫码入口**：真实平台小程序码的私有来源、公有可展示图片、短期场景码、有效期及启停状态；图片本身不含个人或会话数据。
- **微信身份绑定**：平台 AppID 与 OpenID 对应的内部顾客 ID、绑定状态、验证方式、创建/撤销时间和审计；OpenID 不作为用户可编辑属性。
- **小程序会话**：仅保存令牌摘要、顾客 ID、设备/发行时间、到期、撤销状态；与网页 Cookie 会话可区分。
- **购物车/订单/装备/政策**：复用现有服务端领域实体及单件库存；两端不另建平行业务表。购物车按同一顾客作用域持久化，并有版本冲突规则。
- **扫码场景**：短标识映射到允许的公开目标、到期和使用统计；不能映射私人订单访问权。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 网站与小程序各自可独立打开；真实微信扫码入口在具备平台条件后 10 次测试中 10 次打开指定小程序页面，无 AppID/场景错配；未就绪时展示假码数量为 0。
- **SC-002**: 同一门店/日期/顾客的网页与小程序目录、可订数量、订单金额/政策快照、处理阶段一致；至少一笔正常和一笔受损合成订单跨端走到终态。
- **SC-003**: 两端并发抢最后一件时至多一单成功；重复提交造成的重复订单、库存占用或模拟资金事件均为 0。
- **SC-004**: 未绑定、错绑、账号停用、员工身份冒用、他人订单访问及旧令牌重放成功数均为 0；网页和小程序的退出/撤销按预期生效。
- **SC-005**: 顾客能在小程序完成日期选择、筛选、购物车、损坏规则同意、预约及本人订单查询；手机真机和开发者工具的必要页面无阻断性布局/交互错误。
- **SC-006**: AppSecret、`session_key`、平台访问令牌、网页/小程序会话和个人资料在公开二维码、源仓库、公开静态目录与测试日志中的泄露数为 0；公开 AppID 可出现在项目配置中，不能当作密钥。
- **SC-007**: 018 SHOWCASE、017 代理入口、现有 DEMO/CANDIDATE 的完整 Node/浏览器回归通过；未完成合法域名、真实微信平台和真机验收之前，只声明本机适配测试通过，不声明小程序已发布或可扫码使用。

## Assumptions and dependencies

- 第一阶段小程序服务顾客；五类员工和管理员保留网页工作台。若后续要求员工移动作业，应另写角色、离线、设备取证与权限规格。
- 018 安全合成预览已完成本机六角色和恢复验证；019 已用隔离 SHOWCASE 验证跨端业务合约。真实微信平台和手机端验收仍须单独完成，不能由假平台或本机模拟器代替。
- 用户已提供小程序 AppID 和小程序备案号；AppSecret、服务器 HTTPS 合法请求域名及其 ICP 要求、平台审核与发布仍需由用户/主体办理。`bsrski.cn` 网站域名 ICP 审核与小程序备案分开核对。即使服务器选中国香港，小程序业务域名要求也不能自动跳过。平台资格和费用不可在本机代码中替代。
- 首版继续模拟资金和签署；不得为了小程序体验擅自接入微信支付或真实退款。业务正式费率仍待 BSR 批准。
- 正式记账 NOK、Europe/Oslo 时间解释和单件库存原则不变；定位币种只作参考展示。

## Out of Scope

- 获取/配置私有 AppSecret、完成合法 HTTPS 请求域名与其 ICP 条件、审核/发布小程序、对公网开放网站或上传 GitHub；已由用户提供的 AppID 和小程序备案号不再列为待办。
- 把网页打包成 WebView 冒充原生小程序；把小程序前端部署到网页目录；从网页二维码自动传递登录态。
- 微信支付、真实押金托管和自动退款、电子签署、消息订阅/营销推送与员工移动端工作台。
- 使用真实 BSR 顾客或员工资料、正式价格、真实受损照片作为课程预览数据。
