## Summary

保留现有 Web 六角色工作台，新增原生微信小程序顾客端。Web 与小程序调用同一个 Node 服务和单写 SQLite 领域模型。小程序使用微信 `wx.login` 临时凭证，由服务端调用 `code2Session`，再与本站顾客 ID 显式绑定；小程序有独立、可撤销的受控会话。网页扫码入口只在真实微信平台码可用并经发布控制后展示。日期库存、购物车、报价、预约、取货码、订单进度与受损结果统一由服务端裁决；微信平台凭据、真实支付和正式发布不纳入本地实现。

## Technical Context

- **Language/Version**: Node.js 24 ES modules、原生 HTTP/HTTPS、SQLite；微信原生 WXML/WXSS/JavaScript，以真实微信开发者工具验证目标基础库版本。
- **Existing source**: `src/server.mjs`、`src/identity.mjs`、`src/domain.mjs`、`src/fulfillment.mjs`、`src/damage.mjs`、`src/db.mjs`、`public/app.js`；017 可信同机代理，018 合成全功能环境为正式验收前置。
- **New source**: 已建 `mini-program/` 原生顾客客户端、`src/wechat-platform.mjs` 平台登录交换适配、`src/cart.mjs` 持久共享购物车、`src/mini-entry.mjs` 扫码入口状态、`src/mini-identity.mjs` 一次性挑战/显式绑定/令牌撤销与 `src/mini-api.mjs` 独立身份和顾客业务边界。开发者工具项目已配置正式公开 AppID，但默认业务模式仍沿用本机回环演示 API；安全模式源码尚未通过真实微信平台与真机验收。
- **Storage**: 现有单写 SQLite 中已新增微信绑定、一次性挑战/已用码、小程序会话、共享购物车与小程序报价结构。固定 `home` 场景的入口状态由私有启动配置、PNG 和 HMAC 凭据控制，不建扫码状态表；动态场景映射仅在以后引入动态 scene 时设计。私有附件、AppSecret 和平台访问令牌均留在公开目录之外。HMAC 不构成微信签发证明。
- **Network**: 小程序正式环境仅经已登记 HTTPS 合法域名访问相同业务服务；Node 仍在可信代理后回环监听。网页 Cookie/Origin 与小程序令牌认证各走明确边界。
- **Tests**: Node 单元/集成、平台 HTTP 适配器假实现、隔离 SHOWCASE DB、桌面/390px 网页扫码入口及正式 AppID 的开发者工具模拟器；真机与平台交换仍保留未验收。
- **Scale/Scope**: 单实例课程展示和有限老师账户；微信真实请求限额、扫码成功率、外网质量待平台和云端条件具备后测量。

## Implementation Order

1. **冻结基线和依赖**：确认 018 的实测状态、017 入口和当前 Web 订单/购物车/API；保存现有 DEMO/CANDIDATE 数据库摘要、测试数量和网页截图。若 018 未通过，019 跨端交易验收保持阻断。
2. **业务用例与 API 合约先行**：确定顾客浏览、共享购物车、政策同意、预约、本人订单、取货码、扫码进入和账号绑定字段、错误码及可测后置条件。把网页购物车本地状态迁到受控服务端，同时明确未登录临时购物车的合并规则。
3. **数据迁移和测试先行**：增加微信绑定唯一键、小程序会话摘要/到期/撤销及购物车版本；固定首页扫码入口由私有配置和签署凭据控制，无须数据库映射。迁移必须幂等，对现有订单快照无写入。用隔离旧库、双端冲突、重放和对象权限测试验证。
4. **平台适配**：生产接口只接受服务端配置的 AppID/AppSecret，`code2Session` 和获取小程序码通过限时 HTTPS 调用；测试使用明确的注入式假实现，不能在正式配置中落入假实现。平台错误映射为稳定且不泄密的公开错误码。
5. **身份和权限**：小程序通过一次性微信 `code` 建立待绑定状态，顾客证明控制现有账号后显式绑定；发行独立会话令牌、仅存摘要、限制有效期，退出/解绑/停用撤销。员工角色绑定被拒绝。小程序 API 在每次调用检查模式、账号、对象归属和会话。
6. **共享购物车和业务流程**：所有价格、库存和合同规则调用现有服务端领域函数；购物车带版本、重复操作键和报价到期。小程序端做浏览/提交 UI，网页端改用同一购物车 API；员工 Web 更新经原服务端流程写同一订单。
7. **网页扫码入口**：未配置真实码时以可读筹备卡代替；固定首页 `home` 码需私有图片、同一 AppID、签署批准凭据和发布开关，过期后立即隐藏。正式展示还须取得平台签发码并完成真机扫码验收，不附会话或私人订单参数。动态短场景映射只有新增动态入口时才实施。
8. **联调和恢复**：隔离合成实例运行 Node/浏览器测试；用微信开发者工具及真机测试扫码、登录、购物车、预约、跨端更新和手机布局。完成数据库备份、迁移回退和旧会话失效演练。
9. **交付资料**：更新系统需求覆盖、用例规约、模块类图、序列图与核心业务设计需求文档的客户端视角；云端/平台准备另记部署文档。记录已获正式 AppID 和用户提供的小程序备案号，仍将域名 ICP、合法请求域名、真实平台与真机验收及发布标为未完成。

## Rollback and Data Safety

- 019 初始代码默认不开启小程序登录/扫码入口；不配置真实平台凭据不会调用微信 API。不能用降级到公开演示账号作为“继续可用”。
- 数据库结构迁移用新表和索引，禁止重建或改写既有订单/政策快照。迁移前做验证备份和隔离恢复；回退应用版本前确认新表不会破坏旧服务启动。
- 关闭小程序入口可撤销小程序会话、隐藏网页码，网页业务仍可独立运行；不可因撤销码删除已经形成的同一订单。
- 微信密钥若疑似泄露，先撤销/轮换平台密钥和本站会话，再审计绑定及扫码生成记录；公开仓库不得出现私有项目配置。

## Deferred Decisions

- 正式 AppID 与小程序备案号已由用户提供；小程序类目和账号权限、网站域名 ICP、合法请求域名、证书、AppSecret、审核/发布及真机测试资格仍需逐项核定。
- 顾客自助注册是否开放、员工小程序工作台、消息订阅、微信支付及真实退款，均不由 019 自动启用。
- 网站扫描入口正式公开的时间，仍以用户满意后的发布决定为准。
