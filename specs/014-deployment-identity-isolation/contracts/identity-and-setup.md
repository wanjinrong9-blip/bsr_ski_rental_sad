# 014 身份与初始化接口契约

状态：**本机候选已实现核心接口，最终验收仍在进行**。依据 [规格](../spec.md)；实际测试见 [验收指南](../quickstart.md)。本契约仅针对隔离的正式候选验证，不授权公网监听、发布站点或真实交易。默认本地演示的既有接口行为须保持兼容。

## 运行配置和阶段

| 配置 | 候选用途约束 | 演示用途 |
| --- | --- | --- |
| `BSR_RUN_MODE` | 显式设为 `candidate`；未知、空白或冲突值拒绝 | 省略时为 `demo` |
| `HOST`、`PORT` | 仍只允许 013 已批准的回环地址和有效端口 | 沿用 013 |
| `BSR_DB_PATH` | 指向独立私有数据空间；首次初始化时目标文件必须不存在，重启时必须有候选来源标记；禁止演示、未知或不兼容数据 | 沿用原本机演示数据空间 |
| `BSR_BACKUP_DIR` | 必须指向已存在且不在公开资源中的私有备份位置；启动业务服务前须有可验证恢复安排 | 不改变现有备份命令 |
| `BSR_TLS_CERT_PATH`、`BSR_TLS_KEY_PATH` | 指向配对、覆盖回环主机的证书与私钥；私钥不在公开目录或发布产物；应用直接提供本机 HTTPS | 不新增要求 |
| `BSR_PUBLIC_ORIGIN` | 仅允许与回环 `HOST`/`PORT` 和证书一致的安全来源；本机验收夹具为 `https://127.0.0.1:4174` | 不新增要求 |

预检必须为只读操作，先核对所有配置、真实路径边界和已有资料来源。它不能创建目录、数据库、WAL/SHM、用户或监听端口。首次初始化只允许写入候选来源标记、一个权限管理员及必要审计；只有复检通过后，业务服务才可开始。再次启动应识别既有候选来源标记，不要求数据空间仍为空。

### 离线操作员命令

当前入口：`tools/candidate-setup.mjs`，子命令 `preflight` 与 `init-admin`。它们不提供匿名 HTTP 初始化端点。初始化要求目标文件尚不存在；已存在的空文件也不能用来首建。

| 命令 | 输入 | 成功结果 | 拒绝结果 |
| --- | --- | --- | --- |
| `preflight` | 上表候选配置；不接受业务账号密码 | 输出不含秘密的用途、数据来源、备份位置检查与 `needs_init` / `ready` 状态；退出码 0；无文件或网络副作用 | 配置缺项、演示/未知/高版本库、目录越界等返回非零退出及稳定错误类别；不回显秘密或个人资料，不改原数据 |
| `init-admin` | 预检通过且目标文件尚不存在的候选数据空间；由操作员在交互输入中提供操作者标识、首个管理员资料和非预置凭据，密码不显示、不作为命令参数 | 原子地写入候选来源标记、恰好一个管理员与审计，输出不含凭据的账号标识和状态；退出码 0 | 未通过预检、已有目标文件、重复/并发初始化、演示或未知数据空间一律非零退出；不生成第二个初始管理员，不清除原资料 |

不在日志、命令参数、错误消息、浏览器页面或清单中保存明文秘密。初始化中断时，下次预检必须给出明确状态：要么无管理员可重新初始化，要么已有唯一管理员进入复检；不得自动生成另一个账号。管理员凭据遗失时使用后续受控恢复规程，不重复执行首建命令。

### 候选备份恢复契约

入口为离线 `tools/candidate-restore.mjs --backup <文件> --manifest <同名清单>`。操作员须提供完整候选启动环境和 `BSR_RESTORE_OPERATOR`；`BSR_DB_PATH` 必须指向已存在私有父目录内、当前不存在的目标文件。备份与 `.json` 清单必须是 `BSR_BACKUP_DIR` 中的独立普通文件，不接受链接、旧目标覆盖或演示来源。命令先在隔离副本核对清单格式、SHA-256、完整性、外键及 `CANDIDATE/READY` 标记，随后在新目标副本中撤销全部旧会话、提高账号授权版本、写入恢复检查和不含秘密的审计，再独占发布并复检。任何预检失败不创建目标；已发布后的异常保留文件供人工审阅，不猜测清理或覆盖。此命令只供本机隔离恢复，不构成生产故障切换或云端部署。

## HTTP 契约

现有演示模式维持当前响应字段与演示数据，以免破坏课程预览和既有测试。候选模式增加用途标识，并对认证和写入实施更严格规则。所有候选接口由应用在回环地址直接通过 HTTPS 提供；不通过额外代理或任意转发头判定安全来源。

| 接口 | 演示模式 | 正式候选模式 |
| --- | --- | --- |
| `GET /api/health` | 维持本地演示健康响应 | 返回健康状态与 `runMode: "candidate"`；不得包含数据路径、秘密、账号或个人资料 |
| `GET /api/bootstrap` | 维持 `demo: true` 与现有字段 | `demo: false`、`runMode: "candidate"`、`capabilities: {selfRegistration: false, selfRecovery: false, bookingEnabled: false}`；无演示身份信息；未导入获批主数据时 `stores: []` |
| `POST /api/auth/login` | 维持现有演示响应以兼容测试 | 成功 `200`、响应正文仅含安全用户摘要，不含 `sessionToken` 或其他可重用凭据；会话由仅服务端可读、仅安全连接传输的 Cookie 承载。错误凭据 `401`，统一文案 |
| `POST /api/auth/register` | 维持课程演示顾客注册 | 无身份核验渠道时，带合法来源的请求返回 `403`、稳定错误类别 `SELF_REGISTRATION_DISABLED`，无用户创建；后续渠道启用须另行验收 |
| `POST /api/users` | 不改变现有演示入口 | 仅已登录且具授权的管理员可开通员工或经离线核验的顾客测试账号；请求声明岗位、门店或技师范围、核验记录及一次性初始凭据；无权、重复邮箱、无效门店或缺核验记录均拒绝且不创建账号 |
| `PATCH /api/users/:id/state` | 不提供候选管理动作 | 仅候选权限管理员可把账号设为 `ACTIVE` 或 `DISABLED`；重新启用须提供线下核验编号；不得停用首个管理员或改变本人状态。状态变化撤销目标账号旧会话，重复目标状态不额外更改 |
| `POST /api/users/:id/reset-password` | 不提供候选管理动作 | 仅候选权限管理员可在提供线下核验编号后设置目标账号一次性新凭据；不能重置自己；新凭据不可与原值相同。成功撤销目标旧会话并要求其下次登录先改密；响应和审计不含明文凭据 |
| `PATCH /api/users/:id/role` | 保留演示岗位编辑语义 | 候选提升为经理、经营负责人或权限管理员，或改变门店范围时必须提供线下核验编号；不得降级首个管理员。成功更新岗位/门店并撤销目标旧会话，审计只保存核验编号摘要 |
| `POST /api/auth/change-password` | 不改变现有演示行为 | 候选账号用本人现有凭据更换为非预置新凭据；成功撤销旧会话，重新登录后才可执行业务；失败不改变账号 |
| `POST /api/auth/logout` | 维持既有退出 | 成功 `200`、撤销当前会话并清除 Cookie；重复退出可安全返回成功，不恢复会话 |
| `GET /api/me` | 维持现有身份读取 | 有效会话返回当前安全用户摘要；退出、过期、停用、改角色/门店/指派或重置凭据后的旧会话返回 `401` |
| `GET /api/events` | 保留原演示 SSE | 候选须有当前有效会话；会话被撤销、停用或过期时关闭连接，不继续推送业务变更信号；首次改密期间不得进入业务订阅 |

候选 Cookie 应为 `HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`，无 `Domain` 属性，且不在响应正文、脚本可读存储、URL 或日志重复传送。初始设计将候选会话最长有效期设为 8 小时；退出和权限变化立即撤销全部旧会话。演示 Cookie 与候选 Cookie 必须互不通用。具体命名和轮换由实施计划确定，但该可观察行为不得降低。

首个管理员只能使用离线 `init-admin`，不能通过 `POST /api/users` 争抢首建身份。后续账号开通只允许已授权管理员操作；门店租赁专员和经理必须绑定门店，技师按任务指派，跨店岗位必须有明确授权。初始凭据通过线下可信渠道交付，服务响应和审计均不返回明文；新账号首次登录除 `/api/me`、本人改密和退出等必要入口外不得读取或改变业务，也不得订阅业务 SSE。账号停用、角色/门店/技师指派变更以及凭据重置均撤销旧会话。

### 请求来源、限速与错误

- 候选模式全部改变状态的请求，包括登录、退出、用户和订单写入，必须带与 `BSR_PUBLIC_ORIGIN` 完全一致的可信 `Origin`。缺失或不匹配均返回 `403`，不写业务数据；不根据客户端任意提供的转发头放宽来源。演示模式保持既有兼容行为。
- 同一标准化账号或来源在 10 分钟内连续失败 5 次，后续 15 分钟暂停尝试，返回 `429` 与粗粒度 `Retry-After`。不存在的账号与密码错误使用相同对外文案，不能靠响应辨认账号是否存在。限速事件仅审计必要元数据。
- 未认证请求访问受保护对象返回 `401`；已经登录但无对象权限时沿用 012 的拒绝语义，不泄露其他顾客或门店对象是否存在。候选环境未导入获批目录时，预约请求必须失败而非使用演示价目。
- 在候选未接入经 BSR 批准的正式支付、签署和费用政策前，报价、预约、现场开单、付款、合同签署、取还、合同变更、损坏费用复核、补差及退款审批的状态变更入口须返回稳定拒绝，不得生成“成功交易”的演示流水。无获批价目时，候选 `GET /api/catalog` 返回空目录，`GET /api/damage-policy` 不返回演示政策。
- 成功及错误响应继续使用 JSON；错误可增加稳定的非秘密 `code` 字段，保留既有 `error` 文本字段兼容演示客户端。详细堆栈、路径、凭据和完整个人资料不得返回。

## 客户端呈现契约

正式候选登录页不显示统一演示密码、六角色快捷登录或顾客自助注册/自助恢复入口。客户端只依赖 `/api/bootstrap` 的用途和能力标志决定文案；候选模式不读取或写入演示 `sessionStorage` 令牌。页面应继续显示演示资金、合格签署、待批准 NOK 价目等真实限制；“正式候选”不得被写成“已正式上线”。

## 兼容和非目标

- 默认演示模式保留现有登录 JSON 令牌、演示账户、订单和测试用法；014 的严格候选行为不追溯改变演示订单。
- 014 不迁移旧演示库、不导入正式门店和商品、不提供真实支付或合格电子签署、不开放网络入口。旧资料只读检查与隔离恢复演练写在 [quickstart](../quickstart.md)。
- 任何经由本机 HTTPS 得到的成功结果仅证明隔离候选验收，不构成公网部署许可。
