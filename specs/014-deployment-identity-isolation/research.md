# 014 技术研究与决策

日期：2026-11-15  
状态：**计划阶段的设计选择，均未实施或验收**。依据 [spec.md](spec.md)、项目宪章及现有代码；本文件不授权公网监听、云端发布、GitHub 上传或使用真实业务数据。

## D1：运行用途采用显式状态，正式候选分三阶段

**Decision**：新增显式运行用途，省略时保持现有本地演示；未知值拒绝。正式候选依次执行无副作用预检、离线一次性初始化、完整启动。预检检查回环监听、独立数据路径、允许的页面来源、安全连接凭证、私有备份位置及现有数据来源；初始化阶段先验证非预置凭据，再写首个管理员、实例来源标记与审计。只读检查通过前不得调用会创建目录或数据库的入口。完整启动再次验证标记和管理员唯一性。三阶段均保持 013 的回环监听限制。

**Rationale**：[src/server.mjs](../../src/server.mjs) 在模块顶层调用 `openDb()`；[src/db.mjs](../../src/db.mjs) 的 `openDb()` 先建目录/表、填充数据并运行迁移。仅在 `listen()` 前验证不足以保证失败无副作用。离线初始化可避免把一次性管理员开通入口暴露给网页访客。

**Alternatives considered**：在当前启动函数里加一个布尔开关，容易让部分旧写入在预检前发生；把初始化做成未认证网页接口则扩大首启攻击面；直接允许 `HOST=0.0.0.0` 违反 013 与本规格边界。

**Verification/risk**：用新路径、已标记候选库、演示库副本与错误配置逐项比较启动前后目录、数据库和监听。对已有 WAL 库的“只读”检查还须实测是否产生 SHM/WAL 副作用；若有，应改为不修改源库的隔离检查方案。只用 `NODE_ENV=test` 不足以避免打开数据库，因为它目前仅跳过监听。

## D2：正式候选数据有来源标记，旧库绝不静默提升

**Decision**：在实例级元数据中保存唯一实例标识、运行用途、创建时间、结构版本和初始化状态。首次初始化只接受独立空路径；再次启动只接受标为正式候选且结构兼容的数据。无标记旧库、演示标记库、混合资料和不兼容版本均只提供只读阻断报告；不改写原库。现有未标记演示库继续允许在本地演示用途运行。

**Rationale**：目前仅有 `app_migrations` 记录迁移名，没有环境来源。文件名、路径或有无 `@bsr.demo` 账号都不足以证明数据来源。明确标记使“运行用途”与真实数据状态相符，避免先打开再发现演示资料。

**Alternatives considered**：按文件名区分或检查演示邮箱，均可被复制/重命名或混合数据绕过；自动从演示库迁移会改变历史合同、价目与交易语义，超出 014。

**Verification/risk**：同时覆盖空库、标记候选、复制演示库、无标记历史库、部分迁移和新版本库，拒绝场景要求原文件及关键行数不变。来源标记本身不能证明数据真实；后续业务导入仍须独立审计。

## D3：将演示填充与安全结构迁移彻底分离

**Decision**：把演示种子和演示专用补录只放在本地演示路径；正式候选仅创建空业务结构并运行经逐项审查的结构迁移。每次新迁移明确标注是否会写入业务演示数据，候选环境默认不执行后者。候选环境没有获批门店、装备和价目时保持不可预约。

**Rationale**：跳过 `seed()` 仍不够。`openDb()` 会在空库插入固定账号/订单；[src/catalog-upgrade.mjs](../../src/catalog-upgrade.mjs) 的 `upgradeCatalog()` 会另外插入示例护具、库存与价格；[src/db.mjs](../../src/db.mjs) 的 `upgradeOperations()` 补演示排班；[src/fulfillment-schema.mjs](../../src/fulfillment-schema.mjs) 补演示档案、承包费率及“课程演示”来源。现有 [src/rental-policy.mjs](../../src/rental-policy.mjs) 和 `depositRule` 也明确是演示政策，不能自动作为正式价目。

**Alternatives considered**：只跳过主 `seed()`，仍会从其他升级函数产生虚构库存/价目；在写入后删除演示数据会留下审计、外键及历史语义风险。

**Verification/risk**：对新候选库检查 `users`（除首个管理员）、`stores`、`variants`、`units`、`price_policies`、`reservations`、`payments`、`damage_photos` 为零；现有演示库升级前后业务记录语义保持。未来新的目录升级需要继续按此规则审查。

## D4：一次性初始管理员使用离线、原子开通

**Decision**：提供只在本机操作员手中运行的一次性初始化命令。操作员提供非预置、该实例独有的管理员凭据；命令在同一原子操作内建立实例来源、首个管理员及非敏感审计记录。并发和重复调用由数据库约束和状态检查共同保证，只能得到一个初始管理员。秘密不进入命令回显、错误、日志或项目文件。后续管理员管理沿用受授权的后台流程，并针对正式候选补齐受控顾客/员工开通。

**Rationale**：当前 [src/db.mjs](../../src/db.mjs) 固定创建六类演示账号，所有账号共享演示密码；没有独立初始管理员开通流程。让服务启动时自动设定默认管理员会重现相同风险。

**Alternatives considered**：内置统一管理员密码不符合规格；首个访问者网页注册管理员缺少可靠身份依据；仅依赖人工直接改数据库无法形成可重复验收与审计。

**Verification/risk**：重复、并发、中断、弱/预置凭据、旧库和半初始化状态均测试，结果不产生第二个首个管理员。管理员遗失凭据时只能走受控离线恢复，不开放免认证重置入口。

## D5：正式候选使用安全连接承载会话，仍只在本机

**Decision**：正式候选由应用直接在回环地址提供 HTTPS，使用操作员提供的私有证书/密钥及与 `HOST`、`PORT` 一致的安全来源；没有可验证的证书、密钥和来源时不进入业务服务，不依赖代理转发头。服务只通过受保护的浏览器会话机制传递会话凭据，设置安全传输、脚本不可读和严格的同站点属性；不再在登录响应正文、`sessionStorage` 或自定义会话请求头暴露可重用令牌。本地演示路径保留 HTTP 课程预览，不把候选本机 HTTPS 误称为公网 TLS 部署。

**Rationale**：[src/server.mjs](../../src/server.mjs) 当前用 HTTP，登录同时返回 JSON 令牌及无 `Secure` 的 Cookie；[public/app.js](../../public/app.js) 把令牌存入 `sessionStorage` 并添加 `x-bsr-session`。候选环境若继续纯 HTTP 或脚本可读凭据，就不能达到规格中的会话边界。

**Alternatives considered**：只添加 `Secure` 属性而继续在响应正文返回令牌，仍可被页面脚本取得；依赖浏览器对纯 HTTP 本机地址的特殊例外，行为不应成为候选模式验收依据；另设本机代理会增加可信转发配置及误配风险，直接配置公网代理则超出本包授权。

**Verification/risk**：在隔离本机 HTTPS 连接下做真实浏览器流程，验证登录、刷新、退出、跨标签及旧会话拒绝。测试证书和私钥临时生成或由操作员提供，不纳入代码仓库；预检核对证书/密钥配对、证书覆盖回环主机及私钥不在公开目录。证书信任仅在隔离测试范围内处理，不通过全局关闭证书验证来取得“通过”。未来公开网络入口须另作部署规格和验收。

## D6：来源保护、会话撤销及登录限速统一进入身份层

**Decision**：候选模式的每次业务写入要求有效会话、精确匹配配置的页面来源及防跨站写入证明；来源缺失、不匹配或证明缺失时拒绝。登录按规格对账号和来源两个维度限制失败频率；错误文案不区分账号是否存在。账号停用、角色、门店、技师指派范围或凭据改变时使此前会话立即失效；退出亦撤销当前会话。自助注册和恢复在核验渠道未接入时关闭，由管理员经离线核验办理。

**Rationale**：[src/server.mjs](../../src/server.mjs) 只在请求带 `Origin` 时比较 `host`，缺失来源会放行；登录无限速；会话表只有哈希和到期时间。`/api/users/:id/role`、`saveEmployee()` 等身份修改没有统一撤销旧会话。页面来源必须比较协议、主机及端口，不能只比较主机名。

**Alternatives considered**：只设同站点 Cookie 无法覆盖所有跨站写入与误配情形；仅在角色修改接口删除会话会遗漏门店与其他身份变更。可在设计阶段比较“所有修改路径集中删除会话”和“账号授权版本与会话绑定”；后者更不易漏掉路径，但需模式兼容迁移。

**Verification/risk**：用 2 名顾客、2 店员工、受派/未受派技师及跨店岗位测试允许/拒绝矩阵；验证来源缺失/伪造、失败 5 次/10 分钟后暂停 15 分钟、退出/角色/门店/凭据变更后旧会话全部拒绝。限速状态应有过期清理，避免共享网络被永久封锁。

## D7：公开界面和业务政策按用途显式呈现

**Decision**：`/api/bootstrap`、登录页及订单费用说明根据运行用途呈现；候选模式隐藏全部演示账号、一键角色入口、统一密码和自助注册入口，禁止把演示汇率、押金、租赁政策或示例目录当作获批业务。无批准主数据时目录为空、下单拒绝。演示模式保留当前课程标记。

**Rationale**：[src/server.mjs](../../src/server.mjs) 的 `/api/bootstrap` 始终返回 `demo:true`；[public/app.js](../../public/app.js) 的登录页显示固定演示密码和角色快捷按钮；当前租赁、押金规则与汇率是示例。只改后端数据、不改页面会误导审阅者。

**Alternatives considered**：使用 CSS 隐藏演示内容但仍返回快捷入口与密码，不满足隔离；为候选环境复制一套前端会增加分叉和维护负担。应采用同一页面中的明确用途控制，并从服务端拒绝演示入口。

**Verification/risk**：两种用途分别检查登录、目录、报价、订单和说明；不将候选界面的空目录解释为业务已可用。获批主数据导入属于后续独立工作。

## D8：备份与敏感路径沿用 011/013 并补真实路径边界

**Decision**：候选预检要求业务库、备份、照片、日志与配置位于不公开的独立空间；备份目标同时检查词法路径与最终真实路径，对已存在父目录的符号链接/Windows junction 做边界判断。既有 011 完整性、外键、清单哈希及隔离恢复继续用于候选测试；生成的备份仍按含个人资料的私有文件处理。

**Rationale**：[tools/backup-verify.mjs](../../tools/backup-verify.mjs) 对 `public` 的备份禁入仅做字面路径比较，可能被目录链接绕过；[src/startup-config.mjs](../../src/startup-config.mjs) 已有更严格的候选路径真实位置判定。备份可能包含顾客资料、会话和受损照片，`.gitignore` 不是发布或访问控制。

**Alternatives considered**：只依赖 `.gitignore` 不能防止静态服务或手工打包泄露；把正式候选备份直接上云涉及加密、保管、调度和批准，超出 014。

**Verification/risk**：覆盖普通目录、词头相似兄弟目录、路径链接和 Windows junction；从隔离副本恢复并比较订单金额、合同版本和库存号。加密、异地保管及正式恢复时间目标仍是后续部署验收项。

## 计划阶段的兼容和未决风险

1. 所有新测试及恢复演练须使用隔离数据空间；`NODE_ENV=test` 目前只阻止监听，不阻止 `openDb()`。不得修改现有 `data/bsr.sqlite` 或旧备份。
2. 013 的合法回环配置和静态资源真实路径防护、011 备份、012 对象授权须回归。演示模式默认账号与既有订单不能因为 014 被重置。
3. 候选安全连接的证书来源、浏览器信任方式和命令入口须在实施任务中写成可执行步骤；本研究没有安装证书或开放网络。
4. 正式业务仍缺支付、退款、合格签署、BSR 价目批准、隐私保留政策和容量验收；014 的“正式候选”不得被发布文案解释为“已上线”。
