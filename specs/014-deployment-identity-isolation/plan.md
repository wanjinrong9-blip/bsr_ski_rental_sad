## Summary

在保留默认课程演示的同时，增加只读预检 → 离线一次性管理员初始化 → 正式候选服务启动三阶段。新候选数据空间从空库建立并记录来源，不运行任何演示种子或演示升级写入；旧演示/来源不明/不兼容库均只读拒绝。候选会话仅由受保护的浏览器凭据承载，增加来源校验、登录限速和权限变更后撤销。服务仍受 013 本机监听闸门约束；真正公开访问和真实交易另行立项。

## Phase 0 — Research Decisions

设计取舍、证据和备选方案见 [research.md](research.md)。核心决定：

1. 启动前预检不得 `import` 会立即打开数据库的服务入口；离线操作员命令只读检查，然后在事务中写入来源标记与首个管理员，最后由服务入口复检。
2. 候选库只从空库建立。现有 `openDb`、`seedDemoOrders`、`upgradeCatalog`、`upgradeOperations`、`upgradeFulfillment` 均须拆开“结构/历史迁移”和“演示填充”；不能只跳过 `seed()`。
3. 数据空间有明确来源。无标记旧库可继续作为本地演示打开，但候选拒绝；带候选标记的数据空间也不能被演示模式打开或填种子。
4. 候选登录仅返回用户摘要，将会话放在脚本不可读取且仅安全连接传递的凭据中；演示模式保留旧 JSON 令牌以兼容现有课程测试。候选前端与照片/合同请求不再读浏览器会话存储。
5. 所有候选写入（含登录、退出）要求可信来源；按账号及来源执行规格限速。角色、门店、技师指派和凭据变更撤销旧会话，同时保持 012 的逐对象授权。
6. 候选由现有服务在**回环地址直接提供本机 HTTPS**，演示仍用原本机 HTTP；证书与私钥均由操作员提供到私有路径，预检验证其配对及与允许来源一致。这样无需可伪造的转发头或额外代理，也不得把 `HOST` 改成对外地址。测试夹具不能复用真实秘密。

### 启动、迁移与回退顺序

1. 先对现有演示库使用 011 的方法做可校验备份，不在原数据空间开发或试验候选模式。
2. 在独立路径完成只读预检，拒绝通过路径别名指向公开目录/备份混用/旧库；输入错误不得创建父目录、SQLite 文件或监听。
3. 候选初始化先验证凭据非预置与唯一，后在原子事务中建立结构、来源标记、首个管理员和审计；并发/失败不留下半初始化的可服务实例。若文件已建立但事务失败，标记为不可服务并给出清理/重试流程，不自动删除文件。
4. 服务启动先只读核对来源、模式、已完成初始化与 schema 版本，再运行允许的结构迁移和监听。正式候选不调用任何演示填充分支；没有批准门店/价目时客户预约关闭。
5. 回退首先停止候选服务，保留源库与审计，使用隔离备份恢复并在恢复后撤销全部旧会话；不通过演示模式打开候选库，也不删除已有演示数据。结构迁移不兼容时以前置备份恢复，不把回滚理解成简单删除新列。

### 身份与交互边界

- 候选会话使用短期有效期、明确撤销和回环 HTTPS 上的受保护凭据；当前 `x-bsr-session` 与响应体 `sessionToken` 仅留在默认演示。退出、停用、角色/门店/指派或凭据变化会让旧候选会话失效。
- 候选所有改变状态的请求校验明确允许来源；缺失 Origin 也拒绝。浏览器直接连接回环 HTTPS 服务，服务不采信任意转发头。来源拒绝及登录限速在读取/变更业务对象之前执行。
- 顾客自助注册和自助恢复在无核验渠道时关闭；候选增加仅授权管理员可用的受控账号开通与离线核验后恢复，初始凭据通过线下渠道交付，首次登录先改凭据。门店岗位绑定门店，技师按任务指派，经营及权限管理保持已定义跨店范围。
- UI 根据候选能力值隐藏角色快捷登录、统一密码与注册入口；`/api/bootstrap` 和订单费用说明不把演示汇率、价目、损坏/超时政策当作已批准事实。正式交易接口继续阻断或标明未接入。
