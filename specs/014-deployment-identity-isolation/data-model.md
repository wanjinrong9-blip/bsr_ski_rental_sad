# 014 数据模型：运行来源、身份与会话

日期：2026-11-16。此文件描述 014 的目标与当前本机实现；候选使用独立新数据文件，**没有把现有演示库迁为候选**。保留 005–013 已有的订单、合同、单件库存、NOK 价目和审计主键。

## 1. 运行来源与初始化

### `runtime_installation`（计划新增；每个数据空间恰好一条）

| 字段 | 类型/约束 | 意义 |
| --- | --- | --- |
| `singleton_id` | 整数主键，固定为 1 | 阻止同一库出现多个运行来源。 |
| `run_mode` | `DEMO` / `CANDIDATE` | 数据空间创建用途；不随进程变量任意改变。 |
| `instance_id` | 不可复用随机标识，唯一 | 日志、备份清单和检查结果的关联键；不是访问秘密。 |
| `schema_version` | 非负整数 | 结构兼容检查；高于当前程序时拒绝打开。 |
| `init_state` | `INITIALIZING` / `READY` / `BLOCKED` | 首次候选初始化与业务服务门槛。 |
| `initialized_at` | 时间或空 | 完成一次性初始化的时间。 |
| `initial_admin_id` | `users.id` 或空 | 完成后的首个权限管理员。 |

**规则**：

- 当前实现仅允许从**不存在的目标文件**初始化候选；已有空文件也拒绝。旧演示、无标记、混合和不兼容库一律只读拒绝候选用途。
- 新演示库标为 `DEMO`；既有无标记库可继续原本机演示，但候选不得接管。带 `CANDIDATE` 标记的库在演示用途下也应拒绝，避免自动填入演示订单。
- 来源标记、首个管理员和初始化审计应在同一原子边界提交。若数据文件已产生而事务失败，`READY` 不能出现，服务不能打开；文件不自动删除，由操作员审阅。
- 来源标记只证明创建路径，不证明所有历史资料真实；若检查发现演示账号/订单或来源冲突，转入拒绝路径。

### `runtime_checks`（计划新增；只保存初始化与启动检查摘要）

| 字段 | 约束 | 意义 |
| --- | --- | --- |
| `id` | 主键 | 检查编号。 |
| `instance_id` | 对应来源标记 | 区分数据空间。 |
| `phase` | `INIT` / `START` / `RESTORE` | 检查阶段。 |
| `result` | `PASS` / `BLOCK` | 结果。 |
| `reason_code` | 受控枚举 | 不含敏感路径或秘密的原因。 |
| `checked_at` | 时间 | 追溯。 |

只读预检失败时不得为记录审计而写入目标库；由离线命令输出非秘密检查结果，操作员可另存于私有运维位置。成功初始化后的检查才可写入该表。

## 2. 账号与授权

### `users`（现有表的候选扩展）

保留 `id`、`email`、`password_hash`、`role`、`store_id` 和个人资料。计划新增 `account_state`（`ACTIVE`/`DISABLED`）、`provisioning_method`（`OFFLINE_ADMIN`/`VERIFIED_SELF`）、`verified_at`、`must_change_password` 和 `auth_epoch`（整数，初值 1）。现有演示账号保留原语义，不能因为迁移填充这些字段而变成候选可用身份。

约束：租赁专员和经理须绑定一门店；技师访问具体指派的维修对象；经营负责人和权限管理员有明确跨店范围。候选顾客在无在线核验渠道时仅能由管理员经离线核验开通。后续账号凭据线下交付且首次登录仅能更改凭据，不能直接执行业务。角色、门店、任务指派或凭据变更提升相关账号的 `auth_epoch`，使旧会话失效；对象授权仍每次查当前业务归属。

### `initial_admin_event`（计划新增）

记录 `instance_id`、管理员 `user_id`、操作员标识、时间及结果；不保存密码、一次性秘密或会话令牌。仅首次候选初始化可插入成功事件；重复/并发初始化返回冲突而非新建账号。初始管理员若遗失凭据，只允许受控离线恢复，不开启未认证网络重置入口。

## 3. 会话与失败尝试

### `sessions`（现有表的候选扩展）

保留令牌**哈希**、`user_id` 和 `expires_at`；计划增加 `issued_at`、`auth_epoch`、`revoked_at`。候选请求须同时满足：会话未过期/撤销、账号启用、会话 `auth_epoch` 等于账号当前值，以及请求对象当前仍允许访问。退出或管理员撤销使会话失效；角色/门店/任务/凭据变化提高授权版本，旧会话不再通过。演示继续兼容现有会话接口，候选不向脚本返回原始令牌。

### `auth_attempt_buckets`（计划新增）

按账号标识摘要与来源摘要分别保存 `window_started_at`、`failed_count`、`blocked_until`；只保存最小必要数据，定期清理过期桶。10 分钟内连续失败 5 次后暂停 15 分钟；成功登录后只清理符合政策的计数，不让一个来源永久冻结全部合法用户。请求错误不区分“账号不存在”与“密码错误”。多实例一致性不在 014 范围内，公开部署前须复核限速存储与入口。

### `audit_log`（沿用）

增加受控的运行用途、初始化、登录成功/失败/限速、来源拒绝、会话撤销、账号授权变更事件。只记事件类型、账号/来源摘要、时间和结果；不得把凭据、完整个人资料或照片写入审计详情。无账号的失败事件可没有 `actor_id`。

## 4. 与业务数据及备份的关系

- `stores`、`variants`、`units`、`price_policies`、`reservations` 在新候选初建后均为空；没有经 BSR 批准的数据导入时，候选服务不得接受预约。演示模式继续保留种子与旧测试行为。
- 结构升级与演示回填分开执行。现有 `catalog-upgrade` 还会插入多种示例商品、库存和价目；`upgradeOperations`、`upgradeFulfillment` 也有针对演示账号的回填，候选路径必须跳过这些业务填充。
- 备份清单应关联 `instance_id`、运行用途、结构版本、完整性和哈希；备份、照片、日志以及配置不得位于公开静态目录或经链接指向该目录。恢复到隔离位置后应撤销候选会话，再验证订单金额、合同版本及库存号。
- 014 不改写历史订单、合同版本、押金、退款或单件身份。真实支付/签署与正式商品/价目导入由独立工作包决定。

## 5. 状态转移与不变量

```text
不存在的数据空间
  ├─ 演示启动 → DEMO / READY（仅本机，允许演示种子）
  └─ 候选只读预检通过 → 仍不存在（只取得 needs_init 结果）
       └─ 一次性管理员 + 来源 + 审计原子提交 → CANDIDATE / READY

DEMO、无标记旧库、来源不明或高版本 ─候选启动→ BLOCK（原资料零改动）
CANDIDATE / READY ─演示启动→ BLOCK（不得写入演示种子）
CANDIDATE / INITIALIZING 或 BLOCKED ─业务启动→ BLOCK
```

任何可服务的候选库必须只有一个来源标记和一个首个管理员初始化成功事件。任何对模式/数据来源的拒绝均不能通过切换界面或监听地址绕过。数据恢复后新的会话世代必须使恢复前令牌无效。
