# 014 隔离验收指南与实施记录

**状态：本机隔离功能包验收完成（2026-11-17）。** `tools/candidate-setup.mjs`、候选模式及独立测试已经加入；本文件区分已运行证据与正式运营尚需的验收。测试仅用临时数据空间，候选应用在 013 回环限制内直接提供本机 HTTPS。这里不记录真实密码、令牌、顾客资料或公网地址。

## 前置条件

1. 使用项目要求的 Node.js 版本；在 `bsr-app` 项目根目录运行。保留现有本地演示数据和备份，不直接用 `data/bsr.sqlite` 作候选测试。
2. 准备一个隔离的新数据空间、私有备份目录和互不混用的候选测试凭据。所有测试资料用虚构姓名与邮箱；密码通过交互输入或测试夹具提供，不放入命令参数、截图或提交文件。
3. 为候选浏览器验证准备覆盖 `127.0.0.1` 的本机测试证书与私钥，放在隔离私有目录；应用直接在 `https://127.0.0.1:4174` 提供服务。没有可信的本机证书与 HTTPS 时只能执行离线预检，不能把普通 HTTP 的会话结果当作通过。
4. 依据 [接口契约](contracts/identity-and-setup.md) 检查候选配置及预期错误类别。正式支付、真实签署、商业费率、容量和网络发布不属于本验收。

## B. 候选离线预检和首个管理员

以下命令是**已实现的操作入口**。在本机新建私有临时目录并替换路径示例；不要展示任何秘密，也不要指向 `data/bsr.sqlite`：

```powershell
$env:BSR_RUN_MODE = 'candidate'
$env:HOST = '127.0.0.1'
$env:PORT = '4174'
$env:BSR_DB_PATH = '<隔离的私有目录>\candidate.sqlite' # 此文件必须尚不存在
$env:BSR_BACKUP_DIR = '<隔离的私有备份目录>'
$env:BSR_TLS_CERT_PATH = '<隔离的私有证书路径>'
$env:BSR_TLS_KEY_PATH = '<隔离的私有密钥路径>'
$env:BSR_PUBLIC_ORIGIN = 'https://127.0.0.1:4174'
node tools/candidate-setup.mjs preflight
node tools/candidate-setup.mjs init-admin
node tools/candidate-setup.mjs preflight
```

初次预检只读并返回 `needs_init`；初始化在交互提示中输入操作者和首个管理员资料，不向终端回显密码；复检返回 `ready`。只允许创建一个首个管理员及必要来源/审计记录。再次或并发运行 `init-admin` 应拒绝且管理员总数保持 1。配置检查失败不得创建数据库、目录、WAL/SHM 或监听。`init-admin` 拒绝已存在的目标文件，即使该文件为空；中断后生成的未完成文件不能自动重用或删除，需操作员先审阅。

## C. 无副作用拒绝矩阵

对每一项均用新的隔离测试路径，记录退出码、非秘密错误类别、目标路径创建情况和端口状态：

| 变体 | 预期 |
| --- | --- |
| 未知或空白 `BSR_RUN_MODE` | 拒绝，不猜测候选用途 |
| `HOST` 为非回环地址 | 沿用 013 拒绝，不开放访问 |
| 候选 HTTPS 证书或私钥缺失、配对失败、未覆盖回环主机或落入公开目录 | 拒绝，不开放业务访问 |
| `BSR_DB_PATH` 位于公开资源或经链接进入公开资源 | 拒绝，不创建数据库 |
| 数据路径已含演示账号/订单 | 只读拒绝，原资料不变 |
| 数据路径已有来源不明或不兼容版本资料 | 只读拒绝，原资料不变 |
| 初始化时缺少非预置凭据或首个管理员信息 | 初始化失败，业务服务不开放 |
| `BSR_BACKUP_DIR` 缺失或位于公开资源 | 拒绝，不生成备份 |
| `BSR_PUBLIC_ORIGIN` 缺失、非安全来源或与实际入口不一致 | 拒绝，不开放业务访问 |
| 初始化中断、重复或并发 | 不出现第二个首个管理员；复检给出明确状态 |

至少覆盖前八类独立缺失/冲突场景，核对 SC-001 的零副作用目标。现有演示库只用副本做检查；演示原库及备份不得作为破坏性测试对象。

## D. 新候选实例与身份契约

1. 通过应用的本机 HTTPS 地址打开登录页和 `GET /api/bootstrap`：应见 `runMode: candidate`、`demo: false`、`selfRegistration: false`、`selfRecovery: false`；不见演示账号、统一密码、快捷角色入口或演示商品。空目录下预约被拒绝。
2. 以隔离测试管理员和受控顾客/员工夹具登录：成功响应正文没有 `sessionToken`；会话只通过受保护 Cookie 维持。浏览器脚本可读存储、地址和日志中没有可重用凭据。普通 HTTP 不可作为候选登录成功证据。
3. 对 `POST /api/auth/register` 发送允许来源请求：无核验渠道时返回 `403 SELF_REGISTRATION_DISABLED`，用户数不增加。授权管理员经离线核验后开通一名顾客与各岗位测试账号；无权开通及缺核验记录均拒绝。新账号首次登录只允许更换一次性凭据，完成后才进入业务；门店员工绑定本店，技师按对象指派，跨店岗位仅用其明确的汇总权限。
4. 用两个顾客、两个门店的租赁专员/经理、受指派与未指派技师及跨店角色组成矩阵，分别尝试本人和他人的订单、维修照片、库存与人员记录；应只允许授权对象，所有越权读写拒绝且无副作用。
5. 同一账号或来源 10 分钟内连续失败 5 次，第 6 次应受 15 分钟暂停并返回 `429`；对存在和不存在账号的对外错误文案保持一致。等待窗口结束或按受控恢复路径后，合法登录可以继续。
6. 候选模式所有写入，包括登录和退出，请求来源缺失/不匹配时返回 `403`，数据不变。允许来源的正常操作继续可用。退出、账号停用、角色/门店/指派范围变更或凭据重置后，旧会话请求返回 `401`，重新登录才取得新授权。

## E. 历史资料与恢复演练

对演示库副本、缺少来源标记的副本和版本不兼容副本分别运行候选只读预检；三者都须拒绝，原文件及关键订单记录保持一致。按 011 的既有备份流程，在隔离位置恢复一个受控副本；比较订单 NOK 金额、合同版本和单件库存标识。该演练只验证可恢复性，不执行历史资料迁移。候选实例不得把演示资料自动导入。

### 候选备份的离线恢复命令

`tools/candidate-restore.mjs` 只接收经 011 清单验证的**候选**备份，目标 `BSR_DB_PATH` 必须是预先建立的私有父目录中的**不存在文件**；不得指向运行实例、`public` 或备份目录。恢复使用与启动一致的候选环境变量，另设 `BSR_RESTORE_OPERATOR`（线下操作员标识），并从 `BSR_BACKUP_DIR` 中选定 `.sqlite` 与同名 `.sqlite.json` 清单：

```powershell
$env:BSR_RUN_MODE = 'candidate'
$env:BSR_DB_PATH = '<新的私有目录>\restored-candidate.sqlite'
$env:BSR_BACKUP_DIR = '<原私有备份目录>'
$env:BSR_RESTORE_OPERATOR = '<线下操作员标识>'
# HOST、PORT、BSR_TLS_CERT_PATH、BSR_TLS_KEY_PATH、BSR_PUBLIC_ORIGIN
# 同 B 节的候选配置；目标文件当前不能存在。
node tools/candidate-restore.mjs --backup '<私有备份目录>\candidate-backup.sqlite' --manifest '<私有备份目录>\candidate-backup.sqlite.json'
node tools/candidate-setup.mjs preflight
```

命令在隔离副本核对 SHA-256、完整性、外键、来源 `CANDIDATE/READY`，独占发布到新目标文件；恢复副本增加账号授权版本并撤销备份中的旧会话，写入不含秘密的恢复审计。错误哈希、演示备份或已存在目标均拒绝且不覆盖原文件。成功后仍需操作员人工核对门店、订单金额、合同和库存，再决定是否启动本机候选；本命令不提供生产故障切换。
