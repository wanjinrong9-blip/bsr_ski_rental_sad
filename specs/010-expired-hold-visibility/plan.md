# Implementation Plan: 暂留到期状态与重新预约引导

**Feature**: [spec.md](spec.md)  
**Date**: 2026-11-04  
**Status**: 本地实施并验证

## 技术方案

- Node.js 原生 HTTP + SQLite WAL；不增加表和运行依赖。
- 在领域层提供 `effectiveReservationStatus(row, at)`。仅对原始 `HOLD` 比较服务器到期时刻并返回 `EXPIRED`，不写数据库。
- `orderDetail` 在生成列表、详情、员工视图及流程图之前应用同一推导；去重重放使用同一函数。
- `orderWorkflow` 给过期预约明确的终止状态与顾客负责人；顾客、店员页面根据 `EXPIRED` 展示下一步。原签约/付款守卫保持；补齐取消守卫。
- 库存算法及提醒算法已经按到期时刻排除 `HOLD`，沿用同一时间语义，不在读取提醒时修改原始行。

## 宪章检查

1. UC-04/05/06、FR-C07、页面、接口、测试与 PDF 说明使用同一业务含义。
2. NOK 报价和押金快照保留为历史；不将失效报价描述成可付金额。
3. 到期释放库存后仍须在新预约提交时重新校验，避免超卖。
4. 顾客对象权限和技师隐私范围不因新状态扩张。
5. 无迁移；隔离数据库测试先验证，运行数据库只作只读核验。回退仅需回退代码与文档。

## 验证与限制

- `node --test test/*.test.mjs`：46/46；`node test/preview-smoke.mjs`：包含顾客过期订单 UI 路径。
- 运行数据库原始 `HOLD` 行保持可审计；`EXPIRED` 是 API 生效状态，不应写作独立持久状态。
- 真实支付回执、生产多实例时钟、外部通知和业务方政策审批仍需上线前专项工作。
