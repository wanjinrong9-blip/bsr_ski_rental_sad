# Contract: 线上合同签署与演示付款

此处描述现有 HTTP 服务需要达到的目标语义，不表示第三方支付或合格电子签署已接入。

## 1. 创建预约

`POST /api/reservations`：顾客本人提交门店、租期、装备、技能与政策同意。成功返回 `HOLD`、订单号和原有 15 分钟暂留截止；无演示付款流水。失败不得占用库存或形成部分订单。

## 2. 开具与读取当前合同

`POST /api/reservations/{id}/contracts`：顾客仅能为本人有效且未开具过合同的 `HOLD` 订单发起；员工/经理沿用现有现场权限。返回不可变快照、版本和摘要。合同记录的发起人与快照中的门店经办责任人分列，顾客自助不会写入员工开单归属。无经办人、过期、非本人或重复开具均拒绝。

`GET /api/reservations/{id}/contracts` 和 `GET /api/contracts/{id}/print`：继续按本人或授权岗位读取；历史版本只读，不返回无关顾客正文。

## 3. 签署当前合同

`POST /api/contracts/{id}/sign`：请求包含主动同意、姓名和所见快照摘要。顾客本人记录 `CUSTOMER_ACK`，员工只可在见证实际纸质签署并填写说明时记录 `PAPER_WITNESS`。当前版本、暂留有效且摘要匹配才成功；重复签署、旧版本、过期和越权返回拒绝。

## 4. 确认演示付款

`POST /api/reservations/{id}/pay` 与现场 `POST /api/operations/reservations/{id}/pay`：共用领域门槛。必须为有效 `HOLD`，当前版本合同已签，且合同宽限资格与订单当前资格一致。先校验，后在同一事务内生成 RENT、DEPOSIT 各一笔演示流水，转 `CONFIRMED` 并创建准备任务。签署缺失返回冲突和下一步提示，金额/版本变化要求重新预约或重新生成可签版本；重复提交不新增流水。

## 5. 前端状态映射

| 当前事实 | 顾客主动作 | 店员/经理可见 |
| --- | --- | --- |
| 有效 `HOLD` 且无合同 | 生成并阅读合同 | 可协助开具；不得收款 |
| 有效 `HOLD` 且当前合同未签 | 查看并确认合同 | 可见签署待办；纸质见证需真实依据 |
| 有效 `HOLD` 且当前合同已签 | 确认演示付款 | 可见已签；现场可按凭证确认演示收款 |
| `CONFIRMED` / `READY` | 查看取货码、备货进度 | 拣货和安全检查；交付时仍核当前合同 |
| 暂留过期 | 重新预约 | 不可继续原单签付 |

所有金额仍为 NOK；界面文字必须明确是演示付款和电子确认。
