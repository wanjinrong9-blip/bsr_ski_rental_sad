# Feature Specification: 门店与订单对象授权

**Feature Branch**: `012-store-object-authorization`（Spec Kit 逻辑标识；当前项目未初始化 Git）  
**Created**: 2026-11-07  
**Status**: 本地实现与验证完成（2026-11-10）；正式跨店轮岗制度待 BSR 确认  
**Input**: `usecase/系统规约.md` 的最小权限要求、`requirement.txt` NFR-01、宪章 IV，以及现有员工可读取全部门店订单和经营/管理员可读取顾客业务详情的实现缺口。

## 业务价值与执行者

BSR 多门店共享库存与经营事实，门店租赁专员和门店运营经理应处理自己门店的订单，经营负责人及平台运维管理员只需汇总指标。顾客可以在任意 BSR 门店归还装备，接收门店需要知道本批实物和归还截止，不需要看到非本店顾客的完整档案、合同、押金、受损照片或历史订单。

| 系统执行者 | 允许的订单范围 | 价值与限制 |
| --- | --- | --- |
| 顾客 | 本人订单 | 查看本人的完整订单及授权证据；不能枚举他人订单 |
| 门店租赁专员 | 所属门店订单；凭精确取货码或订单号受理跨店归还 | 自店可履约；外店仅见本批归还必需字段 |
| 门店运营经理 | 所属门店订单；凭精确码受理跨店归还 | 自店可复核与管理；不能因经理角色访问其他门店顾客资料 |
| 经营负责人 | 跨门店汇总 | 查看总量、营收和库存汇总；不读取单笔订单、顾客身份或私有证据 |
| 平台运维管理员 | 平台运行汇总和权限配置所需最小账号元数据 | 不因管理员角色获得顾客业务详情；账号权限管理另按 UC-15 限字段 |
| 装备检修技师 | 本人指派维修/鉴定任务 | 仍按任务对象授权，不因门店规则扩大视野 |

## 用户场景与验收

### US1 自店员工履约，外店订单不可枚举（P1）

**给定**两家门店各有订单，**当**第一店员工打开订单列表、按 ID 查详情或调用合同、备货、受损、核价等业务入口，**则**仅能查看或操作第一店订单；第二店订单及顾客资料不出现在列表、提醒、搜索和间接接口中。跨店直接请求返回拒绝且不改变业务状态。经理同理；自店正常操作与顾客本人查看不退化。

### US2 跨店归还仅提供最小接收资料（P1）

**给定**顾客把第一店租出的装备交到第二店，**当**第二店员工输入完整且正确的取货码或订单号，**则**系统仅在订单仍处于租赁中时展示归还截止、本批尚未归还单件的库存编号、名称与尺码，以及本店归还入口。员工逐件记录无损、待清洁或疑似损坏及必要备注，系统保留接收人和实际接收门店；押金/损坏核价仍由有权的原门店岗位处理。错误码、猜测 ID、模糊检索或已结清订单不得取得外店资料。

**异常**：外店员工尝试修改请求中的归还门店、额外单件、费用或订单 ID，服务端拒绝且不写入；接收后只返回本次受理回执，不升级为完整订单读取权限。部分归还后，其他未还实物继续占用库存。

### US3 经营与平台角色保持汇总视角（P1）

经营负责人和平台运维管理员可看其职责所需的汇总视图和按门店/状态统计的提醒计数，但提醒不得列出单笔订单 ID、编号、姓名或处理人。两者不能通过直接订单 ID、列表、合同打印、照片、准备单、提醒详情或其他关联接口读出顾客姓名、电话、邮箱、地址、取货码、单笔金额与私有证据。管理员配置账号角色所需的最小账号标识不等于顾客业务订单授权。

## 功能要求

- **FR-001**：每次订单相关读取和写入均由服务端按当前账号、角色和 `store_id` 核验对象归属；不能仅凭前端隐藏导航或请求体传入的门店 ID 授权。
- **FR-002**：员工/经理订单列表只包含所属门店；详情、备货、合同、打印、受损、门店复核、核价、收款、取货、换装等直接或间接入口执行同一归属判断。
- **FR-003**：经营负责人和平台运维管理员的业务订单列表及详情不可用；跨店汇总继续可用，但响应不得含单笔或顾客识别字段。权限管理所需账号元数据属于独立授权面，不能附带订单或私有证据。
- **FR-004**：跨店归还必须先用完整订单号或取货码精确定位仍在租赁中的订单；接收视图只暴露该批归还必需字段，不显示顾客身份、联系方式、押金、合同、受损照片、历史订单或内部备注。
- **FR-005**：跨店归还写入须再次核对精确码、订单仍在租赁中、提交单件仍未归还、当前员工所属门店有效；实际归还门店由服务端固定为员工所属门店，不能由客户端指定他店。原门店的复核责任与订单归属保持不变。
- **FR-006**：对象授权失败无任何业务写入、通知或敏感响应；错误消息不泄露其他门店订单是否存在。跨店接收成功只给最小回执。
- **FR-007**：门店或岗位变更后，新请求按最新服务端身份/门店判断；已产生的合同、NOK 金额、归还记录与审计不回写。
- **FR-008**：员工/经理的订单提醒按所属门店筛选；经营负责人和管理员仅可查看按门店、业务状态聚合的计数，不返回可反查单笔订单或顾客的提醒记录。
- **FR-009**：店员/经理的员工名册只列所属店员工及完成维修指派所需的技师候选；店员班次仅本人，经理班次和每日排班仅所属店；经理不能编辑外店班次或将外店员工排入本店。
- **FR-010**：店员/经理的逐件库存列表只含所属店实物；跨店供给协调使用按门店/状态聚合数量。经营负责人和管理员可看跨店库存汇总，但不因汇总权限获得逐件库存编号、成本或检查备注。

## 质量要求与边界

- 验收须覆盖两门店、两员工、经理、顾客、经营负责人和管理员的直接/间接 HTTP 路径，以及真实浏览器工作台；失败写入的订单状态、库存、押金和审计数量应保持不变。
- 不新增业务方未批准的跨店销售或跨店取货权；跨店例外仅限实物归还接收。正式岗位轮岗与临时授权制度待 BSR 确认。
- 当前本地演示仍使用种子账号与模拟资金；本特性不声称完成生产身份认证、隐私合规或多实例安全审计。
