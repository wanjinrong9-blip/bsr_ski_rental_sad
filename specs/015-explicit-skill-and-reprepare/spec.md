# Feature Specification: 显式滑雪水平与重新备货释放

**Feature Directory**: `specs/015-explicit-skill-and-reprepare`  
**Created**: 2026-11-17  
**Status**: 已实施并完成本机范围验证；BSR 业务批准和正式上线另行验收  
**Input**: 关闭历史 005 复核中可独立验证的两项缺口：新订单不能以默认值冒充顾客本次自评；重新备货须释放旧单件占用，并证明冲突时不会留下半完成状态。

## User Scenarios & Testing

### User Story 1 - 如实记录每单滑雪水平（Priority: P1）

顾客在线预约时明确选择本次滑雪水平；租赁专员代顾客现场开单时，也必须记录顾客本次给出的水平。门店据此匹配装备，不能把未填写当作“初级”。历史订单若本来没有这项记录，查看时应明确标为“历史未登记”，不补造顾客说过的话。

**Why this priority**: 一条错误的自评可能影响装备匹配和服务安全，也会污染合同快照与后续分析。

**Independent Test**: 分别以顾客线上和店员现场两条入口提交合法与缺失水平的预约，核对页面反馈、订单数量、暂留库存、顾客同意记录及合同快照；再读取一张原水平为空的历史订单。

**Acceptance Scenarios**:

1. **Given** 已选择可订装备和完整日期、顾客明确给出“初级”“中级”“高级”或“专家+”之一，**When** 线上或现场创建预约，**Then** 新订单和随后生成的合同快照保存相同水平，原有租期、NOK 报价和押金计算不变。
2. **Given** 本次水平缺失、为 `null`、空白、非文本或不属于四个支持等级，**When** 任一入口提交，**Then** 订单创建被拒，明确提示选择本次水平；不产生订单、提交标识、损坏规则同意、暂留或库存占用。
3. **Given** 一个无效提交标识在水平缺失时首次被拒，**When** 顾客补齐水平并用同一标识重试，**Then** 可正常创建一单；已成功的标识按原有同内容重试与不同内容冲突规则处理。
4. **Given** 历史订单的本次水平原本为空，**When** 顾客或有权限员工查看订单/合同，**Then** 显示“历史未登记”，原订单记录及既有合同快照不变。

---

### User Story 2 - 重新准备时可安全释放单件（Priority: P2）

当已拣选的装备需要重新准备，当前处理人或本店经理记录原因并退回拣选步骤。旧单件不再占着该准备单；另一张有资格的预约可占用它。原订单仍然存在，顾客看到新的备货进度与处理人；未重新完成逐件检查前不能交付。

**Why this priority**: 单件占用若未释放会形成虚假的库存短缺；若重复占用或带着旧检查结果继续交付，又会造成实体库存冲突。

**Independent Test**: 在一个隔离门店中用两张符合租期与库存规则的订单和至少一件实物，完成第一单拣选，执行重新准备，再由另一单尝试拣选该实物；同时检查旧版本、非本店和并发操作被拒后的占用、状态和事件。

**Acceptance Scenarios**:

1. **Given** 一张已拣选且未交付的本店订单，**When** 当前处理人或本店经理以最新版本、至少 3 字公开说明执行重新准备，**Then** 原准备单的全部旧单件占用失效、检查勾选不再有效、状态回到拣选中、版本递增，顾客可见说明和处理人。
2. **Given** 第一单重新准备已成功，**When** 第二张符合可用日期/装备规则的订单拣选，**Then** 可获得已释放且仍可租的实物；第一单再次拣选时须重新核验库存，不得复用旧检查结果或重复占用同一件。
3. **Given** 旧版本、非本店人员、未指派人员、已交付/已取消订单或不足 3 字的说明，**When** 请求重新准备，**Then** 请求被拒；单件占用、准备状态、版本、顾客可见说明和事件数量保持不变。
4. **Given** 两名有权限员工几乎同时操作同一准备版本，**When** 一方重新准备成功，**Then** 另一方的过期操作被拒，最终只有一份有效状态和一套无重复的单件占用。

### Edge Cases

- 水平文本前后空格可去除；仅含空格仍属缺失。数字、对象和数组不能被转成支持等级。
- 无效预约即使拥有可用的提交标识，也不能留下该标识的占用记录；错误不改变已有的成功预约。
- 重新准备时若旧单件后来报修、调拨、清洁隔离或被另一单合法占用，第一单下次拣选必须按当前事实重新判断，不能强取该件。
- 从“装备已备妥”退回重新准备时，订单交付资格同步撤销；旧合同/报价仍保留其历史语义，但新的交付检查必须针对当前准备。
- 顾客同时浏览备货页时，只能看到本人订单的新状态与公开说明，不能看到其他订单或员工内部备注。

## Requirements

### Functional Requirements

- **FR-001**: 新建线上与现场预约须明确提供本次滑雪水平；两处选择控件初始都不能预选一个等级。只接受“初级”“中级”“高级”“专家+”四项。文本前后空格可规范化，缺失、空白、非文本和其他值拒绝，不能默认“初级”。
- **FR-002**: 无效水平的创建请求须返回可理解的字段错误（接口状态 422）；订单、请求幂等记录、损坏规则同意、暂留与库存占用均不得新增或改变。成功订单及相同/不同内容重试沿用现有幂等规则。
- **FR-003**: 有效新订单须将顾客本次水平写入订单及新合同快照；不改变装备自身固定技能等级、NOK 金额、押金政策、报价快照、租期和旧订单。
- **FR-004**: 历史订单的本次水平为空时，读取视图须明确“历史未登记”；不得以默认值回填原记录或重写已生成合同。
- **FR-005**: 重新准备仅允许原订单门店当前处理人或经理，在未交付的允许状态下，凭当前版本和至少 3 字公开说明执行。
- **FR-006**: 成功重新准备须在一个不可分割的业务步骤内失效该订单全部旧单件占用、使旧检查结果不再生效、撤销“已备妥”交付资格、递增准备版本、记录处理人/时间/公开说明，并向本人顾客更新进度。
- **FR-007**: 已释放实物只有在其当前门店、可租、清洁、维修、调拨及日期承诺均允许时才可分配给另一单；同一件不能同时形成两条有效准备占用。
- **FR-008**: 版本冲突、权限不足、状态不允许或说明不合格时，重新准备失败且不改变占用、订单/准备状态、版本、说明、事件或通知。
- **FR-009**: 第一单再次拣选须重新选择当前可用单件并逐项检查尺码、清洁和安全；旧勾选不能用于交付。

### Key Entities

- **预约订单**：归属顾客、门店、日期、状态、本次滑雪水平、冻结报价与合同版本；一个订单有一张当前准备单。
- **顾客本次滑雪水平**：订单事件字段，四种明确选择；与装备规格自身的固定技能等级不同。
- **准备单**：处理人、公开说明、状态、版本和更新时间；顾客本人可查看其进度。
- **准备单件占用**：准备单与物理单件的有效绑定及尺码/清洁/安全检查结果；一件实物同一时刻最多一条有效绑定。
- **准备事件与通知**：处理人、时间、状态和公开说明；仅向该单顾客及有权限岗位可见。
- **合同快照**：订单创建时水平与金额等历史事实的版本记录，不因重新准备或新规则而回写。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 线上与现场两入口的缺失、空白、非文本及不支持等级共至少 8 组隔离样本，拒绝率为 100%；每组新增订单、提交标识、同意、暂留及有效占用数均为 0。
- **SC-002**: 四个合法水平在两入口共 8 组样本中，订单与新合同快照一致率为 100%；历史空值样本 100% 显示“历史未登记”，原记录及合同哈希不变。
- **SC-003**: 重新准备成功后，原准备单有效占用数为 0、版本恰好增加 1、顾客进度可见；在可用规则允许时，第二单能取得释放的实物，第一单不得同时占用它。
- **SC-004**: 旧版本、越权、关闭状态、说明过短及双员工竞争样本全部被拒或由单一成功者定序；失败路径的准备状态、占用、版本、事件与通知差异均为 0。
- **SC-005**: 完整自动回归及隔离浏览器流程通过；在浏览器中可读出本次水平与重新准备后的进度/处理人，390px 页面无整页横向溢出。

## Assumptions

- 本功能先修复现有本地演示流程及其服务端业务约束；014 候选环境仍没有经 BSR 批准的目录、价目和交易政策，因此本功能不开放候选预约。
- 现场员工须向顾客取得本次自评后填写；系统不推断实际滑雪能力，风险提示与装备建议沿用现有规则。
- “重新准备释放”仅指准备阶段的有效单件占用；已经实际交付的实物不在此流程内。
- 日期库存与订单承诺仍按既有 Europe/Oslo 规则判断，正式价格与政策仍待 BSR 确认。

## Out of Scope

- 顾客本人独立确认中途换装、真实差价清算、合格电子签署、奖金、生产容量与跨店轮岗，后续分别立项。
- 修订既有商业费率、8% 押金、超时/损坏规则或自动迁移历史空值。
- 初始化 Git、上传 GitHub、开放本地站点或候选环境的外网访问。
