# Phase 0 Research: 需求与系统模型一致性

**Date**：2026-10-27。依据 `usecase/requirement.txt`、`usecase/系统规约.md`、课程总结、项目宪章、现有应用和 LaTeX 工程。这里只记录建模决策，不把旧图或本地演示视作 BSR 已签字的业务事实。

## R-01 需求编号基线

**Decision**：本轮采用《系统规约》UC-01～UC-15 与需求台账的 FR/DR/BR/NFR 作为主编号。旧 LaTeX `body.tex` 中的 UC01～UC17 及 `updates/uc18.tex`～`uc24.tex` 先建立“旧编号→新用例/拆分/保留原因”映射，再更改正文、图注与交叉引用。

**Rationale**：现有 LaTeX 目录、规约和图片仍使用旧编号；同号不代表同一业务目标。例如旧 UC10 是“自动退还押金”，新 UC-10 是“受损初评、照片鉴定与经理复核”。直接批量替换会产生语义错误。

**Alternatives considered**：保留两套编号并让读者自行猜测（不选）；全局文本替换（不选）。

## R-02 现状证据与改进蓝图

**Decision**：现状流程只画有课程案例、初版需求或实地材料支持的节点；无证据的“人工查表、纸质签署、跨店接收”等具体次序标待访谈。改进蓝图则按 UC 的目标流程画，明确顾客、业务工人、系统和实物实体的职责，另设 BSR 签字确认位。

**Rationale**：课程总结强调现状业务序列图需描述真实业务，蓝图则是未来引入系统后的改进流程。当前没有充分的 BSR 实地访谈记录，不能把本地软件流程倒填为现状。

**Alternatives considered**：把现有软件截图直接写作旧业务现状（混淆事实与目标，不选）；省略现状图（不满足课程要求，不选）。

## R-03 图示分模块与课程样式

**Decision**：保留六章目录，使用老师课件的图例语义与布局原则；分析类图分六组，ERD 分模块，序列图按核心 UC 分张，状态图按复杂对象分张。图首先以可编辑源文件维护，导出清晰图片后嵌入 LaTeX；图号和说明由唯一索引管理。

**Rationale**：旧 `body.tex` 嵌入大量 `media/image*.png`，`updates/` 已有类、序列、状态和 ERD 增补文件；若直接继续叠加，容易产生重复图号、旧规则和不可读的大图。图的业务语义由规约决定，视觉样式由课件示例决定。

**Alternatives considered**：一张全局类图/ERD 覆盖全部字段（难审阅，不选）；只用系统截图代替分析图（不能表达类关系和状态，不选）。

## R-04 分析与数据设计的映射

**Decision**：先从用例字段、事件和规则抽取分析类，再定关系与状态；ERD 由类图映射。主键必须唯一、恒定，1:n 外键在多方，m:n 采用连接实体，自反类别在同表存父引用；合同、价目、费率、同意记录以版本/快照保留历史。图示中的目标模型与当前 SQLite 表分别标注，不把二者差异隐去。

**Rationale**：课程总结将类图视为静态模型、序列图视为边界/控制/实体协作、状态图规范复杂对象，数据层则由类图导出 ERD。现有应用已包含业务表，但不能反过来限制目标需求的表达。

**Alternatives considered**：照搬当前数据库生成 ERD 再称其满足全部需求（无法显示生产缺口，不选）；先写表再补概念模型（追溯链倒置，不选）。

## R-05 文档工程与验收

**Decision**：`usecase/` 的需求和规约为文本基线，`output/BSR设计需求文档_LaTeX/` 为正式排版工程；更新前对旧章节和图片建清单，按六章结构修订，编译后逐页检查可读性、图号、目录和裁切。现有 Node 自动/浏览器测试证明本地演示行为；BSR 商业政策和真实服务另标待决。

**Rationale**：已有 `main.tex`、`body.tex` 与 `updates/` 增补文件，且正文中仍引用旧 UC 编号。编译成功不等于内容一致，必须做文本、模型和版面的双重检查。

**Alternatives considered**：从零另建排版工程（浪费既有版式且增加迁移风险，不选）；只检查 PDF 是否能打开（无法发现旧图文冲突，不选）。

## R-06 范围边界

**Decision**：本功能只生成并核对需求到模型的交付物，不修改预约、库存、费用或权限代码。发现代码缺口时登记到需求覆盖审计，另立可独立验收的实现规格。

**Rationale**：项目宪章要求每份 Spec Kit 功能边界明确，不能以“补齐整个系统”作为不可测的单个实现任务。

**Alternatives considered**：在绘图任务中同时改业务代码与发布环境（范围过大、验证不清，不选）。
