# Implementation Plan: 本地预览启动安全闸门

**Feature**: [spec.md](spec.md)  
**Date**: 2026-11-11  
**Status**: 本地实现及验证完成；执行证据见 [quickstart.md](quickstart.md)

## 技术上下文与设计

- Node.js 24 原生 HTTP 服务入口为 `src/server.mjs`；当前代码在解析配置之前调用 `openDb(process.env.BSR_DB_PATH || data/bsr.sqlite)`，随后用 `HOST` 和 `PORT` 监听。SQLite 的 `openDb` 会创建父目录和数据库，故配置闸门必须放在其前面，不能只在监听前检查。
- 增加无副作用的启动配置验证函数，返回已验证的 `host`、`port`、`dbPath`。入口先算项目根和 `public` 路径、验证全部环境值，再调用 `openDb`。任何错误让进程非零退出，不在失败分支启动 HTTP 服务。
- `HOST` 采用字面白名单，省略才用默认值。`PORT` 先以十进制数字字符串校验，再转整数检查范围；不依赖 `Number()` 对空格、指数或小数的宽松转换。
- 数据库目录边界使用两次判定：一是 `resolve()` 后的词法路径，二是解析最深已存在祖先的 `realpathSync.native()` 后拼接未存在尾段的实际路径。对 `public` 根同样求真实路径，比较时用平台合适的 `relative()` 路径段边界；Windows 对比较用路径大小写折叠。这样覆盖 `public` 内指向外部的链接和外部指向 `public` 的链接。
- `serveStatic` 当前仅检查 URL 解析后的词法路径，随后 `stat()`/`readFile()` 会跟随文件或目录链接。为实际读取目标补充真实路径归属检查，连同 SPA 入口回退目标一起判断；链接逃逸返回 403，不调用 `readFile`。在实现与测试中核查“检查目标”与“读取目标”一致，不能把数据库路径闸门误当作静态文件保护。
- 保留显式相对 `BSR_DB_PATH` 按进程工作目录解释的现有行为；默认仍为项目 `data/bsr.sqlite`。验证函数不写文件、不修改原有合法数据库、不绕过原有迁移和备份流程。若配置错误，标准错误只给配置项和简洁原因，不输出数据库绝对路径或环境变量全集。
- 测试采用 `child_process.spawn` 启动隔离进程与临时路径，检查退出码、文件/目录未产生和端口不监听；正例覆盖默认/合法回环、合法端口、合法旧库。另在隔离的静态目录验证外部文件/目录链接 GET/HEAD 被拒、响应不含秘密，以及正常静态文件可读。进程正常启动后终止子进程并清理隔离测试目录。Windows junction/符号链接测试在可创建时执行，无法创建时明确报告未覆盖。

## 宪章核对

1. **业务价值与追溯**：对应 NFR-01/06 和课程本地预览边界；不改变预约/租金/库存业务语义。README 与覆盖审计必须区分目标和实测。
2. **合同金额真实性**：不修改 NOK 报价、合同、支付或退款。启动失败不打开数据库，因此不发生业务写入。
3. **库存一致性**：正常启动继续使用同一数据库；拒绝时无迁移或库存状态变化。
4. **最小权限与隐私**：限制固定演示账号被意外暴露到网络，阻止数据库落入静态资源目录及静态链接读取私有文件；不把该闸门当作正式认证。
5. **可验证变更与恢复**：先做隔离测试，运行全套回归与浏览器本地预览；真实运行库若需启动前后验证，先使用 011 在线备份机制核对可恢复性，不修改备份工具。

## 验收与回退

- 先运行新隔离测试，再运行 `node --test test/*.test.mjs` 和本机浏览器流程。对危险配置验证非零退出、未创建数据库/目录/WAL/SHM、未监听；对链接逃逸验证 GET/HEAD 拒绝且不泄露内容；对合法配置验证 `/api/health`、正常静态资源与已有持久库仍可用。
- 测试结果填写 [quickstart.md](quickstart.md)，同步 README、需求覆盖审计和必要的设计需求文档说明；未测试前保持“待实施”状态。
- 回退只回退启动配置验证代码与文档。若运行库被不当配置写入过 `public`，须先保护和迁移该数据，不能通过回退安全闸门继续在公开目录运行。

## 明确不包含

云端发布/网络对外开放、真实支付/签章、正式身份认证、TLS 与反向代理、生产数据库和备份制度。本机闸门不能作为正式云端可部署的证明。
