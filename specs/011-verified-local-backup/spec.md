# Feature Specification: 本地数据库可验证备份

**Feature**: `011-verified-local-backup`（Spec Kit 逻辑标识，尚无 Git 仓库）  
**Created**: 2026-11-07  
**Status**: 本地实施并验证

## 用户场景

### US1 运维人员取得可恢复的备份（P1）

平台运维管理员在部署、升级或课程演示前，可生成一份完整的本地数据库备份，并获知备份路径、完整性和关键记录数。正在运行的系统可以继续接受操作；备份必须包含尚在数据库日志中的已提交订单、合同与受损照片。

### US2 在副本中验证恢复（P1）

管理员可以在隔离目录复制并打开备份，检查结构、外键和关键记录；演练不能覆盖正在运行的数据库。失败时不得报告“备份成功”。

### US3 保护敏感数据（P1）

备份可能包含顾客资料、会话与照片，默认存入不提交到仓库的私有数据目录。报告只含文件名、哈希、记录数与验证结果，不输出顾客身份、联系方式、令牌或照片。不会自动上传云端或删除旧备份。

## 功能要求

- **FR-001**：从运行中的数据库建立一致性快照，包含所有已提交记录，不依赖直接复制主文件。
- **FR-002**：生成唯一文件名；完成后验证数据库完整性、外键与核心表记录数，计算 SHA-256 并保存机器可读清单。
- **FR-003**：在新的隔离目录进行恢复副本演练，并与备份的哈希和记录数核对；报告通过/失败。
- **FR-004**：任何备份、验证或演练失败都返回非零退出状态，不将未通过的暂存文件标为正式备份；运行数据库保持原样。
- **FR-005**：备份目录默认不在静态资源目录，且被未来 Git 提交忽略；命令不能输出敏感业务正文。

## 验收标准与边界

- 有未检查点 WAL 写入时仍能备份并恢复订单与 BLOB；原数据库在备份后继续写入不改变快照。
- 备份文件或清单被篡改后，验证返回失败；演练只在隔离副本执行。
- 本功能证明单机演示数据可恢复，不等于异地备份、生产 RPO/RTO、多实例故障切换或自动调度已完成。
