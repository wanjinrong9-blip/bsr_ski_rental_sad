# Implementation Plan: 本地数据库可验证备份

**Feature**: [spec.md](spec.md)  
**Date**: 2026-11-07

## 技术方案

- 使用当前 Node.js 24 `node:sqlite` 的在线备份接口，从只读连接创建一致性 SQLite 副本，避免直接复制处于 WAL 模式的主文件。
- 先写唯一暂存文件；用只读连接执行 `integrity_check`、`foreign_key_check`、核心表行数及 SHA-256 检查；在临时目录复制并重新打开完成恢复演练。全部通过后才发布备份和 JSON 清单。
- 默认源为 `data/bsr.sqlite`，目标为 `.gitignore` 忽略的 `data/backups/`；保留旧备份，不自动删除或上传。命令可指定隔离测试源/目标。
- 不修改业务表、HTTP API、角色权限和前端。对运行实例只读；不进行真实数据库替换。

## 宪章检查

1. 对应 NFR-03/05 与交付前可恢复要求；明确运维管理员收益和失败后置。
2. 原合同、NOK 金额与规则快照逐字节保存，不执行迁移。
3. 使用数据库一致性备份，覆盖 WAL 内已提交的库存与订单变化。
4. 备份仅存私有目录，不随静态资源或仓库暴露。
5. 自动测试覆盖正常、WAL、BLOB、篡改、失败清理和隔离恢复；再对运行数据库执行一次只读备份与演练。

## 回退与限制

删除命令代码即可停止新备份；已生成的备份须按管理员的数据保留政策处理，不自动删除。真实云端部署前仍需加密、异地保管、定期调度与 RPO/RTO 验收。
