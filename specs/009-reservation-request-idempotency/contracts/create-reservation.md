# Create Reservation API Contract

适用：`POST /api/reservations`、`POST /api/operations/reservations`。

请求头 `Idempotency-Key` 须为 16–128 个 ASCII 字母、数字、点、下划线、冒号或连字符（不含空格）；正文保持既有字段。当前登录账号与渠道、请求头共同定义一次提交。现场端目标顾客 ID 仍在正文中。

| 结果 | HTTP | 响应/副作用 |
| --- | --- | --- |
| 新订单 | 201 | 原 `id,code,status,quote` 加 `replayed:false`；一次同意、通知与审计 |
| 相同意向重放 | 200 | 同一 `id,code,quote`、当前 `status`、`replayed:true`；不重新报价或延长暂留 |
| 缺请求头 | 428 | 说明必须携带提交标识；不创建预约 |
| 格式错误 | 400 | 指出有效格式；不创建预约 |
| 同标识不同内容 | 409 | “提交标识已用于不同预约内容”；不创建预约 |
| 内容本身无效/缺货 | 既有 4xx | 事务回滚，键不被占用；修正后可用同键或新键重试 |

不同账号或不同渠道使用相同随机字符串相互隔离；它不能作为查询订单的访问凭据。重放已付款、取消或过期订单返回现有状态，客户端再按该状态继续操作。
