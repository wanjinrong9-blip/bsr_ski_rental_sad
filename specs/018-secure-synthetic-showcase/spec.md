# Feature Specification: 安全合成数据全功能预览

**Feature Directory**: `specs/018-secure-synthetic-showcase`  
**Created**: 2026-11-18  
**Status**: Phase 1–5 与六角色本机浏览器业务验收完成；实际仓库发布包检查与云端发布仍待完成  
**Input**: 用户希望在购买阿里云服务和域名前完成系统准备，让老师将来能以受控账号检视六角色完整流程；此前 017 已完成可信本机代理演练，正式候选环境仍禁止未获批交易。

## User Scenarios & Testing

### User Story 1 - 管理员建立独立的合成预览环境（Priority: P1）

权限管理员在完全空白的私有资料空间中，明确选择“合成预览”，录入自己的强凭据，初始化标记为虚构的门店、商品规格、单件装备与演示政策，然后以受控流程为顾客、门店租赁专员、门店运营经理、装备检修技师和经营负责人分别开通私有账号。六个角色都没有公开的通用密码；错误资料来源或错误配置在产生业务记录前被拒绝。

**Why this priority**: 完整预览只有在安全、独立且可证明为合成资料的基础上才可以展示。

**Independent Test**: 使用全新临时资料目录初始化并检查六角色登录、资料标识、默认演示凭据拒绝与错误配置的零副作用；无需完成订单即可验收。

**Acceptance Scenarios**:

1. **Given** 空白私有资料目录与有效受控入口，**When** 管理员执行一次显式初始化并开通其余岗位，**Then** 六个唯一账号可分别用私有强凭据登录，目录、装备与演示价目均显示合成预览标识。
2. **Given** 当前目录来自课程演示、正式候选或另一合成实例，**When** 操作者尝试将其作为本次合成预览启动或初始化，**Then** 系统拒绝且原目录字节与业务行数不变。
3. **Given** 初始化未完成、凭据弱、资料目录靠近公开静态资源或入口边界无效，**When** 操作者尝试启动，**Then** 不对外提供角色页面、交易接口或未标记的价目。
4. **Given** 合成预览已完成初始化，**When** 再执行初始化，**Then** 不重复建立用户、装备、价格或订单；不会自动重置私有凭据。

### User Story 2 - 六种角色完成可追踪的模拟租赁（Priority: P1）

顾客选择起租和归还日期区间、门店、规格和实物可用库存，把装备加入购物车，确认明示的 NOK 租金、按参考价值 8% 计算的押金、超时和损坏演示规则后完成预约。系统显示订单、取货码与每一步负责人；店员备货、核码交付和归还，检修技师在 24 小时内记录图片与受损分级，经理复核异常、排班与价格，经营负责人查看跨店汇总，管理员管理账号和审计。模拟收款、退款、补差联系和电子确认在所有角色页面与导出中都被明确标为演示，不构成真实资金或有效签署。

**Why this priority**: 老师需要沿着同一套合成数据观察各角色协同、权限和状态流转，而不是六个互不相干的静态页面。

**Independent Test**: 在一个隔离合成实例中，以六个账号依次执行一笔正常租赁和一笔受损异常租赁；比较顾客、店员、技师、经理、经营负责人及管理员看到的同一订单状态、负责人、金额分项和可操作按钮。

**Acceptance Scenarios**:

1. **Given** 合成库存有两件可用同规格装备，**When** 顾客先选 09:00 后起租至 16:00 前归还的日期区间，**Then** 页面显示该区间真实可承诺数量；预约成功后所有相关岗位同步看到数量和订单进度。
2. **Given** 顾客已阅读并同意演示损坏规则，**When** 提交预约并完成模拟确认与支付，**Then** 订单保留政策版本及租金、逐件 8% 押金、预期归还时间和模拟交易状态快照，不得把模拟资金称为已到账。
3. **Given** 已预约订单，**When** 店员完成备货、核码、验货、出借和收回，**Then** 顾客和相关员工同步看到阶段、处理人和时间；重复操作不能产生第二次扣款、退款或库存占用。
4. **Given** 归还装备疑似受损，**When** 技师在 24 小时内上传鉴定照片并选择分级，经理复核并结算，**Then** 顾客看到损坏费、押金抵扣、应退或补差及模拟联系状态；无损则按规则显示自动模拟退押。
5. **Given** 顾客、技师和经理分别尝试访问无关对象或越权写入，**When** 请求提交，**Then** 均被拒绝且订单、库存、照片和审计状态无异常变化。

### User Story 3 - 操作者可安全重启和恢复合成预览（Priority: P2）

部署操作者可用隔离备份演练重启、恢复或重新建立合成预览，验证来源标记、订单语义和登录撤销。旧候选、课程演示和其他合成实例不得混入；恢复前先备份当前库，失败时保留原库并报告可修复原因。

**Why this priority**: 学校展示可能跨多天；恢复过程不能把合成订单变为正式候选数据或遗留有效会话。

**Independent Test**: 临时合成实例完成一笔订单后备份、重启、隔离恢复并检查订单、外键、来源、会话及演示库字节；不需要云服务器。

**Acceptance Scenarios**:

1. **Given** 已完成初始化的合成实例，**When** 服务重启，**Then** 六角色继续访问同一套合成数据，旧会话按现有会话策略处理且任何模式不会自动切换。
2. **Given** 来源和完整性均合格的合成备份，**When** 操作者在隔离目录恢复，**Then** 订单和政策快照一致，恢复前会话失效，演示/候选目录未改动。
3. **Given** 备份损坏、模式不是合成预览或实例来源不匹配，**When** 尝试恢复，**Then** 拒绝恢复并保留目标原库及其可恢复备份。

### Edge Cases

- 用 `Demo123!`、`@bsr.demo`、公开示例账号、弱密码或从现有演示库拷贝的数据库启动合成预览。
- 新库初始化中断、重复执行，或只完成部分门店/单件装备/政策写入；不得把半成品标为可用。
- 不同角色同时预订最后一件、店员同时备货或归还、技师重复上传与重复评估；库存和模拟资金流水保持幂等。
- 顾客选择跨越夏令时切换的 Europe/Oslo 日期，或窗口与另一个订单/维修隔离冲突；以服务端复核结果为准。
- 顾客未同意损坏规则、协议版本变化、押金不足支付受损费用、超时不足/超过新用户 2 小时宽限；订单展示对应处理分支。
- 附件试图包含真实人像、外部客户资料、危险文件或越权访问；合成预览应限制为合成测试附件并按对象权限保护。
- 代理凭据、Host、Origin、来源地址伪造，或会话退出/停用后重放；在业务读写前拒绝。
- 旧正式候选实例仍须维持预约关闭，课程演示仍仅本机回环；打开合成预览不能放宽这两者。

## Requirements

### Functional Requirements

- **FR-001**: 系统须提供独立且显式选择的合成预览用途。课程演示、正式候选与合成预览三种用途须有不可互换的来源标记、资料目录和启动边界；不能通过修改现有候选的预约开关得到合成预览。
- **FR-002**: 合成预览须使用与正式候选等同的受控 HTTPS 入口、私有安全会话、登录限速、来源保护、权限与对象归属检查；不接受公开共用角色密码。
- **FR-003**: 初始化须为显式、一次性、失败可重试的受控操作；须在标记就绪前完整写入合成门店、分类、规格、单件库存、政策版本与初始管理员；不得导入课程演示账号、订单或附件。
- **FR-004**: 权限管理员须可为顾客、租赁专员、运营经理、检修技师及经营负责人开通独立私有强凭据、停用账号和撤销会话；未开通者不能通过自助注册获得员工权限。
- **FR-005**: 合成预览须提供六角色对应的完整现有工作台与操作权限，包含购物车、日期区间库存、预约、装备准备、交付、归还、损坏鉴定、经理复核、排班、经营汇总、账号及审计；同一业务状态须跨角色同步。
- **FR-006**: 所有金额须分项展示并以 NOK 作为订单记账单位；其他货币仅作标明来源和时间的参考换算。押金按照每件装备参考价值的 8% 在下单时取快照，后续政策变化不得改写旧订单。
- **FR-007**: 模拟收款、退款、补差联系、电子确认和演示政策须在入口、操作按钮、订单、合同与导出中持续明确标识，不得对接真实金融或签署服务，也不得把模拟状态称为真实支付成功或法律有效签章。
- **FR-008**: 预约、库存、备货、交付、归还、受损结算须由服务端检查状态、角色、门店及对象归属；重复请求或并发操作不得重复占用实物或生成重复模拟资金记录。
- **FR-009**: 归还后须显示 24 小时鉴定时限、负责技师、照片与损坏分级；按版本化演示规则展示押金抵扣、应退、补差和员工联系，顾客可查处理进度。
- **FR-010**: 工作台须对需要处理的新增或未解决订单显示提醒；每一步须显示目前状态、处理岗位、具体负责人和时间，且不暴露其他顾客的个人资料。
- **FR-011**: 合成实例须可执行经验证的重启、备份、隔离恢复和失效会话处理；拒绝来源错误或损坏备份时不得覆盖目标库。恢复操作须有可复核记录。
- **FR-012**: 新模式不得改变正式候选交易关闭、课程演示回环访问及现有模式数据；历史库迁移须幂等、保留原语义且不得自动转换用途。
- **FR-013**: 系统须在公开页面和操作说明中显著声明所有店铺、人员、订单、价格和鉴定资料均为虚构；不允许以真实顾客资料、真实支付凭据或真实受损照片充实预览。
- **FR-014**: 全流程须覆盖正常、取消、超时、受损、押金不足、重复提交、并发及恢复场景的自动与真实浏览器验证；任何失败均须记录为未通过，不能把本地测试描述成 BSR 商业验收。

### Key Entities

- **运行实例与来源标记**：用途、唯一实例标识、初始化状态和数据版本；约束资料只能属于一种用途。
- **合成数据集**：明确为虚构的门店、商品类别、规格、单件装备与价格/押金/损坏政策版本，不含真实个人资料。
- **受控账号与会话**：六种角色各自独立的登录标识、授权门店、停用状态与可撤销会话。
- **订单与履约事件**：预约时间段、库存承诺、政策/金额快照、交付归还状态、处理人和时间。
- **模拟交易与鉴定**：分项模拟资金状态、受损照片/分级、抵扣和补差联系记录，始终附有演示语义。
- **恢复记录**：来源核验、完整性结果、恢复时间及会话失效结果，不保存密钥明文。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在干净实例中，六种角色均以各自私有账号完成登录和本职至少一项操作；已知演示账号与密码可登录数为 0，真实顾客记录导入数为 0。
- **SC-002**: 一笔正常和一笔受损的合成订单能由顾客、店员、技师、经理及经营负责人沿同一订单追踪到终态；每个状态显示负责人和时间，订单金额各分项与政策快照可核对。
- **SC-003**: 至少覆盖六角色与本人/他人对象的权限矩阵；越权或伪造来源请求成功读取/写入私有内容的数量为 0。
- **SC-004**: 预约窗口中的剩余单件库存和两名顾客并发抢最后一件的结果准确；重复请求造成的重复占用、模拟扣款或模拟退款数量为 0。
- **SC-005**: 隔离实例完成重启和一次备份/恢复，数据库完整性通过、外键错误为 0、旧会话失效；现有演示和候选目录字节保持不变。
- **SC-006**: 桌面与 390px 手机浏览器均可完成顾客预约和店员交付归还；所有涉及金额/签署的关键页面均可见“模拟/合成”标识，无公网监听或云资源创建。

## Assumptions

- 本包是课程展示的安全合成资料环境；“全功能”表示现有业务工作流可在虚构数据上模拟，不代表 BSR 已批准任何商业政策或真实收付款/签署。
- 一套预览实例为单服务进程、单写入 SQLite 数据库；地域、域名、证书和云实例尚未购买或确定。
- 初始管理员由操作者在私有离线初始化流程中建立；其他五种角色通过管理员受控开通，顾客自助注册默认关闭。账号与凭据由操作者私下传给经授权的老师，文件和仓库中不保存明文。
- 预览商品、人员名称和照片均使用新造的虚构资料；若需示例附件，只使用人工生成的非个人图片。
- 订单日期和门店排班按 Europe/Oslo，正式订单账面单位固定 NOK；定位货币仅参考展示。

## Out of Scope

- 购买或配置阿里云实例、域名、证书、DNS、ICP备案、安全组、公网开放和 GitHub 上传。
- 真实客户资料、真实收款/退款、合格电子签署、真实短信/邮件、正式 BSR 价目/损坏政策批准及法律有效性认定。
- 多实例水平扩展与生产流量容量承诺。
- 将部署或老师受控预览流程写入课程核心业务设计需求 PDF。
